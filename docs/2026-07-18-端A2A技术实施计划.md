### 1.1 接入层

### 1.2 智能层

| 模块 | 职责 | 输入 | 输出 |
|---|---|---|---|
| `Orchestrator.ets` | 轻量编排器：意图分类（规则优先、LLM 兜底二分类）→ 工具调用序列 → 流式产出聚合为协议帧 | 用户消息 parts + 会话上下文 | 帧序列（AsyncGenerator\<A2AFrame\>） |
| `IngestTool.ets` | 摄入流水线：下载文件→上传代理解析→切块→(逐批)embedding→写库→KP 抽取→语义关联 | 文件 Part(url/filename/mediaType) | note_id + 进度回调 |
| `RetrieveTool.ets` | 语义检索：query embedding → 内存向量表余弦 topK → 回表取 chunk 与来源 | 查询文本, topK=5 | RankedChunk[] |
| `SchedulerTool.ets` | 复习调度：算出题集（due KP 按优先级排序）、生成题目（LLM）、判分 | 学习者模型 | QuizItem[] / 判分结果 |
| `LearnerModelTool.ets` | 学习者模型唯一写入口：答题/复习事件→掌握度与稳定度更新（规则引擎，LLM 无权改写数值） | review_event | 更新后的 kp_mastery 行 |
| `LinkTool.ets` | 关联建立：新 chunk 向量与全库做相似度，>τ(0.78 起调) 的跨 note 对写入 note_link | note_id | 关联数 |
| `LLMGateway.ets` | 云端 LLM/embedding 客户端：HTTPS 到自建 Node 代理，SSE 流式接收，超时/重试/降级（无网时回退本地模板话术） | prompt/messages | 流式 token / embedding 数组 |
| `ChipsRecommender.ets` | perception/suggest 处理器：读感知上下文（foregroundApp 等）+ 学习者模型，产出 1~3 条 chip（deepLink 回 App） | perceptionContext | suggestions 帧 |
| `PushEngine.ets` | 主动推送规则引擎（见 §3.3）：定时评估触发条件 → 决定走系统通知还是下次 chips 时带出 | kp_mastery/behavior_log | 推送决策 |

**Orchestrator 意图分发伪代码：**

```typescript
async *handle(msg: A2AMessage, ctx: SessionContext): AsyncGenerator<A2AFrame> {
  const filePart = msg.parts.find(p => p.url);           // 有文件 → 摄入
  if (filePart) { yield* this.runIngest(filePart, ctx); return; }

  const intent = this.ruleClassify(msg.text)             // 规则: 含"复习/考我"→review
              ?? await this.llmClassify(msg.text);       // 兜底: qa / review / chat
  switch (intent) {
    case 'review': yield* this.runReviewSession(ctx); break;
    case 'qa':     yield* this.runQA(msg.text, ctx);     break;
    default:       yield* this.runChat(msg.text, ctx);   // 闲聊也走知识库 persona
  }
}
```

### 1.3 数据层

- **RelationalStore（SQLite）**：单库 `km_agent.db`，version 1，迁移走 `onUpgrade`。（API：`@ohos.data.relationalStore`，标准 API，确定可用）
- **向量存储**：embedding 以 Float32 小端序 BLOB 存 SQLite；检索时一次性加载进 `Float32Array[]`（1 万 chunk × 1024 维 ≈ 40MB 内存，可接受；超 3 万再做分桶/量化）。
- **文件存储**：原始课件与解析文本存应用沙箱 `filesDir/ingest/`；云端解析**即焚不留存**（代理侧不落盘，响应返回后立即丢弃——在代理代码里以注释+无写盘实现作证）。
- **Node.js 代理**（唯一云端组件，无状态）：
  - `POST /v1/chat` — SSE 转发 LLM，Key 存服务端环境变量
  - `POST /v1/embed` — 批量 embedding
  - `POST /v1/parse` — PPT/PDF 一次性文本抽取（P0 允许；P1 下沉端侧）
  - 全部请求写审计日志（时间/端点/token 数/耗时，**不记内容**）

**SQLite 表结构草案：**

```sql
-- 笔记/文档
CREATE TABLE note (
  note_id     TEXT PRIMARY KEY,
  title       TEXT NOT NULL,
  source_type TEXT NOT NULL,          -- 'ppt' | 'pdf' | 'manual'
  source_uri  TEXT,
  summary     TEXT,
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);

-- 知识 chunk
CREATE TABLE chunk (
  chunk_id    TEXT PRIMARY KEY,
  note_id     TEXT NOT NULL REFERENCES note(note_id),
  seq         INTEGER NOT NULL,       -- 文档内顺序
  heading     TEXT,                   -- 所属章节标题
  content     TEXT NOT NULL,
  token_count INTEGER,
  created_at  INTEGER NOT NULL
);
CREATE INDEX idx_chunk_note ON chunk(note_id);

-- 向量（与 chunk 1:1，分表便于 P1 换端侧 embedding 时整表重建）
CREATE TABLE embedding (
  chunk_id  TEXT PRIMARY KEY REFERENCES chunk(chunk_id),
  dim       INTEGER NOT NULL,
  vector    BLOB NOT NULL,            -- Float32 小端序
  model     TEXT NOT NULL,            -- embedding 模型版本，换模型按此过滤重算
  updated_at INTEGER NOT NULL
);

-- Obsidian 式双向关联（无向：存小 id 在前）
CREATE TABLE note_link (
  link_id     INTEGER PRIMARY KEY AUTOINCREMENT,
  src_note_id TEXT NOT NULL REFERENCES note(note_id),
  dst_note_id TEXT NOT NULL REFERENCES note(note_id),
  link_type   TEXT NOT NULL,          -- 'semantic' | 'manual'
  score       REAL,                   -- 语义相似度
  created_at  INTEGER NOT NULL,
  UNIQUE(src_note_id, dst_note_id, link_type)
);

-- 知识点（学习者模型的粒度单位）
CREATE TABLE knowledge_point (
  kp_id   TEXT PRIMARY KEY,
  name    TEXT NOT NULL UNIQUE,
  aliases TEXT                        -- JSON array，合并同义 KP
);

-- chunk ↔ KP 多对多
CREATE TABLE chunk_kp (
  chunk_id TEXT NOT NULL REFERENCES chunk(chunk_id),
  kp_id    TEXT NOT NULL REFERENCES knowledge_point(kp_id),
  weight   REAL NOT NULL DEFAULT 1.0,
  PRIMARY KEY (chunk_id, kp_id)
);

-- 掌握度（学习者模型核心表，只允许 LearnerModelTool 写）
CREATE TABLE kp_mastery (
  kp_id          TEXT PRIMARY KEY REFERENCES knowledge_point(kp_id),
  mastery        REAL NOT NULL DEFAULT 0,    -- 0~1，存储值=上次复习后的即时掌握度
  stability      REAL NOT NULL DEFAULT 1.0,  -- 记忆稳定度 S（天）
  last_review_at INTEGER,
  next_due_at    INTEGER,                    -- 下次到期时间戳
  review_count   INTEGER NOT NULL DEFAULT 0,
  correct_count  INTEGER NOT NULL DEFAULT 0,
  streak         INTEGER NOT NULL DEFAULT 0, -- 连续答对
  updated_at     INTEGER NOT NULL
);

-- 学习行为记录（事件溯源，掌握度可重算）
CREATE TABLE review_event (
  event_id    INTEGER PRIMARY KEY AUTOINCREMENT,
  kp_id       TEXT NOT NULL,
  session_id  TEXT,
  event_type  TEXT NOT NULL,          -- 'quiz' | 'review_done' | 'skip'
  grade       INTEGER,                -- 0~5（SM-2 评分）
  response_ms INTEGER,
  created_at  INTEGER NOT NULL
);
CREATE INDEX idx_event_kp ON review_event(kp_id, created_at);

-- 全场景行为日志（喂给 PushEngine 与 chips）
CREATE TABLE behavior_log (
  log_id     INTEGER PRIMARY KEY AUTOINCREMENT,
  ts         INTEGER NOT NULL,
  scene      TEXT NOT NULL,           -- 'ingest'|'qa'|'review'|'chips'|'push'
  action     TEXT NOT NULL,
  payload    TEXT,                    -- JSON
  context_id TEXT,
  task_id    TEXT
);

-- 推送记录（防骚扰审计）
CREATE TABLE push_record (
  push_id     INTEGER PRIMARY KEY AUTOINCREMENT,
  rule_id     TEXT NOT NULL,
  kp_id       TEXT,
  priority    INTEGER NOT NULL,       -- 1高 2中 3低
  shown_at    INTEGER NOT NULL,
  user_action TEXT                    -- 'accepted'|'dismissed'|'ignored'
);
```

## 3. 学习者模型设计

### 3.1 掌握度计算（规则引擎，LLM 不参与数值）

每次作答产生 grade g∈[0,5]（选择题：对=4、错=1；主观题由 LLM 判分映射 0~5，但**只输出 g，不碰 mastery**）：

```
即时更新（复习时刻）:
  答对 (g≥3):  mastery ← mastery + α·(1 − mastery)·(g/5),   α = 0.35
  答错 (g<3):  mastery ← max(0, mastery − β·(3−g)/3),       β = 0.30
稳定度（类 SM-2）:
  答对: S ← S · (2.5 + 0.2·(g−3))      // g=4 → ×2.7
  答错: S ← 1.0, streak ← 0
到期: next_due_at = last_review_at + S 天
```

### 3.2 遗忘衰减（Ebbinghaus 指数模型）

```
当前有效掌握度:  M_eff(t) = mastery · exp(−Δt / S)     Δt=距上次复习天数
```

- 衰减**不落库**：展示与推送判定实时算 M_eff；只有再次复习时才先把 mastery 折算成 M_eff 再做 §3.1 更新（保证事件可溯源）。
- 新摄入未复习的 KP：mastery=0，S=1d，走"预习"通道而非"复习"通道。

### 3.3 主动推送触发规则（PushEngine，每 30 分钟评估一次）

| # | 规则 | 触发条件 | 优先级 | 通道 |
|---|---|---|---|---|
| R1 | 到期复习 | due KP 数 ≥ 3（next_due_at ≤ now） | 高(1) | chips + 系统通知 |
| R2 | 遗忘悬崖 | ∃KP: mastery ≥ 0.6 且 M_eff < 0.5 | 高(1) | chips + 系统通知 |
| R3 | 新摄入预习 | 24h 内有新摄入且 KP 从未复习，当前在晚间档 19:00–21:30 | 中(2) | chips |
| R4 | 学习节律 | behavior_log 统计出的常用学习时段到了、今日无会话且有 due 项 | 低(3) | 仅 chips |

**防骚扰机制（硬约束）：**
1. 每日主动推送 ≤ 2 条；任意两条间隔 ≥ 4h；静默时段 22:30–08:00 不推。
2. 同一 rule 连续被 dismiss 2 次 → 该 rule 静默 3 天（查 push_record）。
3. R1/R2 命中同一 KP 时合并为一条；高优先级抢占当日额度。
4. 系统通知走本地提醒（HarmonyOS 通知/提醒能力，**具体用 notificationManager 还是 reminderAgent 需查阅官方文档确认**）；chips 不算推送额度，是被动透出。

## 6. 演示脚本（3 个连贯场景）

**前置**：真机预置《操作系统第2章》笔记（已有关联关系），现场导入《第3章》。

**场景一 · 30 秒冷启动摄入**（文件交换 / 长时任务伴随 / 自定义卡片 / suggestions）
对小艺说"把这份课件加进我的知识库"并发出 PPT → 对话胶囊实时滚动"解析中→向量化→关联旧笔记" → 完成弹出摄入结果卡片：12 个知识点、与第2章建立 3 条关联 → 口播一句总结（ttsText）。
*评委看点：长时任务伴随全程可感知 + "30 秒生成摘要+预习卡片+关联旧笔记"的冷启动承诺。*

**场景二 · 带引用的知识问答**（对话交互 / 流式 / 多轮 / 澄清 / 引用源卡片）
问"LRU 和 LFU 有什么区别？"→ 流式回答，底部引用源卡片点开是《第3章》原文摘录 → 追问"那它适合什么场景？"（多轮消歧）→ 再问"页面置换讲的是什么？"触发澄清帧"第2章还是第3章？"。
*评委看点：答案可追溯（引用源卡片）+ 端侧知识库隐私卖点："这些都在端上，没出这台手机"。*

**场景三 · 晚上它来找你复习**（chips 主动推荐 / 复习会话 / 学习者模型闭环）
切到微信前台，唤起小艺 → chips 第一条"该复习「页面置换」了（3个知识点到期）" → 点入进入复习会话：复习卡片逐题作答，答错「Clock算法」→ 对话胶囊显示掌握度下降并自动排入明晚复习 → 结束展示掌握度变化卡片，打开 App 热力图亲眼看到颜色变化。
*评委看点：系统上下文感知的主动服务 + "自迭代学习伙伴"核心差异点闭环。*
