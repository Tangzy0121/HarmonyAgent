# loci Remotion 演示视频制作计划

**日期：** 2026-07-24

**状态：** 规划完成，待实施

**工作分支：** `codex/remotion-demo-video`

**产品基线：** `master` 合并提交 `33d88f5`

**实施范围：** 基于当前 `admin/` 移动端高保真原型制作一条程序化产品演示视频，不修改或扩展产品需求。

## 1. 目标

- 使用 Remotion 将 loci 当前已经完成的核心学习闭环组织成一条连续、可复现的产品演示视频。
- 让观众在一分钟内理解 loci 的核心价值：资料经过理解、验证和关联，最终成为可继续学习的知识路径。
- 保留真实原型的视觉质感、页面结构和产品状态，不在视频工程中复制一套新的产品界面。
- 建立可重复使用的截图、镜头、字幕和渲染流程，使原型更新后能够低成本重新生成视频。
- 第一阶段先完成无旁白动态样片，确认叙事、构图和节奏后再决定是否加入旁白、音乐和完整字幕。

## 2. 制作结论

采用“真实原型画面 + Remotion 镜头编排”的混合方案：

1. `admin/` 继续作为产品界面的唯一真实来源。
2. 在仓库根目录新增独立的 `video/` Remotion 工程。
3. 使用自动化脚本从真实路由和交互状态捕获固定尺寸画面。
4. Remotion 负责手机画框、镜头推进、画面聚焦、点击提示、场景转场、标题和声音。
5. 需要连续交互的少量镜头优先使用状态序列模拟；只有地图拖拽等确实需要连续运动的场景才嵌入短视频片段。

不直接录制一整段人工操作，也不把 `admin/` 页面组件整体复制到 Remotion 中。前者难以稳定复现，后者会形成两套需要同步维护的界面实现。

## 3. 输出规格

| 项目 | 第一版规格 |
|---|---|
| 成片比例 | 16:9 横版 |
| 分辨率 | `1920 × 1080` |
| 帧率 | `30fps` |
| 目标时长 | `55–65 秒` |
| 产品画面视口 | `390 × 844`，高分辨率捕获 |
| 输出格式 | MP4 / H.264 |
| 第一轮声音 | 无旁白；可保留临时节奏音轨 |
| 第一轮用途 | 叙事、镜头和视觉方向评审 |

后续可以基于同一套 Composition 增加竖版或短版，但不在第一轮同时制作多比例版本。

## 4. 核心叙事

> 一份资料进入 loci，经过理解、验证与关联，最终变成可继续学习的知识路径。

视频不按导航栏目逐页介绍，而是沿当前已经实现的核心学习闭环展开：

```text
今日重点
  → 知识库资料
    → Agent 阅读结果
      → 深入理解
        → 判断验证
          → 学习完成
            → 地图发生变化
              → 安排下一次

关键页面
  → 打开 Agent
    → 基于当前上下文继续提问
```

## 5. 第一版分镜

| 时间 | 场景 | 产品内容 | 镜头与动效 |
|---|---|---|---|
| 0–4 秒 | 品牌开场 | loci、五瓣花、核心主张 | 黑白底色建立；五瓣花以轻微体积和描边出现；字标淡入 |
| 4–12 秒 | 今日重点 | 今日主卡片、学习安排、最近进度 | 手机画面进入；镜头轻推至主卡片；关键文字按阅读顺序出现 |
| 12–22 秒 | 理解资料 | 知识库、机器学习第三章、Agent 阅读结果 | 从资料封面匹配转场到章节理解页；聚焦“这一章在回答什么” |
| 22–34 秒 | 深入学习 | 解释、判断验证、学习完成 | 使用连续剪辑呈现阅读、选择、反馈和完成；不展示无关操作 |
| 34–44 秒 | 知识变化 | 地图变化页、目标节点、安排下一次 | 完成结果收束为节点；镜头拉开显示关系变化；主出口被明确点按 |
| 44–53 秒 | 学习地图 | 完整节点地图与知识关联 | 使用缓慢平移和轻微缩放展示整体结构；保持节点干净、克制 |
| 53–59 秒 | Agent 问答 | 默认 Agent 面板、全屏问答、上下文引用 | Agent 从当前页面展开；展示一轮提问与回答；输入框保持简洁 |
| 59–63 秒 | 品牌收尾 | loci 与结束语 | 手机画面退出；回到五瓣花与字标；结束语稳定停留 |

## 6. 视觉与运动原则

- 延续当前中性黑白、编辑式排版、克制玻璃材质和五瓣花锚点。
- 视频背景不重新创造另一套品牌空间；使用暖白、浅灰和小面积黑色建立层级。
- 五瓣花只用于开场、收尾和少量场景衔接，不在每个镜头重复出现。
- 手机画面保持真实比例，不使用夸张透视、旋转手机或漂浮式 3D 模型。
- 页面内部的运动应解释来源、去向或状态变化，不为热闹而添加漂浮元素。
- 转场以淡入、匹配剪辑、定向擦除和轻微推拉为主，不使用高强度发光、故障、粒子爆炸或复杂 3D 翻转。
- `spring()` 使用较高阻尼，避免弹跳感破坏 loci 的稳定气质。
- 所有镜头运动基于帧数确定，不依赖运行时随机值，保证预览和最终渲染一致。

4. 深入学习解释页。

6. 判断验证选择状态。
7. 判断验证反馈状态。
8. 学习完成页。
9. 地图变化聚焦页。
10. 今日学习结果页。

捕获脚本优先直接进入稳定 hash 路由，并通过明确的测试标识或组件选择器进入交互状态，不再依赖中文文本匹配。所有素材从当前原型重新生成，不把 `docs/worklog/` 中的历史评审截图直接当作最终视频素材。

## 9. 实施阶段

### 阶段 A：视频工程基线

- 在 `video/` 创建空白 Remotion 工程。
- 注册 `LociDemo` Composition。
- 固定 `1920 × 1080`、`30fps` 和初始 63 秒时长。
- 建立统一的颜色、字体、间距、镜头和缓动令牌。
- 确认 Remotion Studio 能预览并输出测试 MP4。

### 阶段 B：自动化素材捕获

- 扩展或重写当前 `admin/scripts/capture-v2.mjs` 的状态捕获能力。
- 使用固定视口、设备像素比和等待条件。
- 为关键页面状态建立可重复的捕获命令。
- 检查字体、滚动位置、弹窗、抽屉和地图视口的一致性。
- 为素材生成清单，避免 Composition 引用缺失或过期文件。

### 阶段 C：镜头组件与视觉基线

- 完成手机容器、真实界面画面、点击提示和字幕组件。
- 完成品牌开场与收尾。
- 建立场景间的统一安全区和标题位置。
- 制作 10–15 秒视觉样片，先确认画框比例、镜头速度和转场克制度。

### 阶段 D：核心学习闭环

- 按分镜完成今日、知识库、理解、解释、验证、完成和地图变化场景。
- 将每个场景拆为命名 `Sequence`，集中在 `timeline.ts` 管理帧数。
- 使用状态截图之间的匹配剪辑表达点击结果。
- 地图变化使用节点聚焦和镜头拉开表达，不新增产品状态。

### 阶段 E：地图与 Agent

- 完成学习地图的平移、缩放和节点聚焦镜头。
- 完成 Agent 默认面板、全屏状态和一轮问答。
- 保证 Agent 仍表现为来自当前页面上下文，而不是独立聊天产品。

### 阶段 F：节奏、声音与字幕

- 先输出无旁白版本确认整体节奏。
- 根据评审结果决定是否增加中文旁白。
- 如加入旁白，先锁定文稿和时长，再按语句调整镜头。
- 配乐保持低存在感；点击、页面切换和节点更新只使用轻量声音反馈。
- 字幕保持短句和高对比，不遮挡手机界面重点区域。

### 阶段 G：渲染与验收

- 在 Remotion Studio 完成逐帧检查。
- 使用 CLI 输出最终 MP4。
- 检查首帧、末帧、转场边界、字体加载、截图清晰度、声音峰值和黑帧。
- 在至少两种播放器中检查成片。
- 将最终视频、封面帧和结果文档写入 `docs/worklog/prototype-building/results/`。

## 10. 主要交付物

- `video/` Remotion 工程。
- 可重复运行的原型状态捕获脚本。
- `LociDemo` 主 Composition。
- 一条 55–65 秒无旁白动态样片。
- 确认后的一条最终 MP4。
- 一张视频封面帧。
- 一份结果文档，记录实际时长、素材清单、渲染命令和验收结论。

## 11. 验收标准

1. 视频只展示当前原型已经存在的页面、状态与产品能力。
2. 观众无需旁白也能理解“资料 → 理解 → 验证 → 关联 → 下一次学习”的主线。
3. 产品画面来自当前真实原型，不出现历史版本或重新绘制后不一致的页面。
4. 页面文字在 `1920 × 1080` 成片中可辨认，关键内容不会因镜头缩小而失去信息层级。
5. 手机画面、字幕和品牌元素之间不存在遮挡或安全区冲突。
6. 转场克制、连贯，不出现与 loci 调性不符的炫技动画。
7. 动画在任意帧可稳定复现，Studio 预览与最终渲染不存在明显差异。
8. 没有缺图、闪帧、黑帧、字体跳变、图片拉伸或音频突变。
9. Remotion 工程可通过单一命令启动预览，并可通过单一命令输出 MP4。
10. `admin/` 原型构建仍然通过，视频工程不改变产品运行逻辑。

## 12. 明确不在本批次实现

- 新的产品功能、页面、数据或交互出口。
- 后端、真实 Agent、真实文件解析或实时数据接入。
- 一次性同时制作横版、竖版、短版和多语言版本。
- 面向用户的视频编辑器或批量视频生成服务。
- 云端渲染、Remotion Lambda 或自动发布流水线。
- 复杂 3D 手机模型、粒子系统和高强度视觉特效。
- 在第一轮样片确认前购买配乐、配音或商业素材。

## 13. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 原型继续修改导致画面过期 | 所有正式素材由捕获脚本生成，并在最终渲染前统一刷新 |
| 中文字体在渲染时变化 | 字体文件放入 `video/public/fonts/`，等待字体加载完成后再渲染 |
| 页面状态依赖人工点击而不稳定 | 使用 hash 路由、测试标识和明确等待条件进入状态 |
| 视频工程复制产品实现 | 只复用截图、短视频和必要品牌 SVG，不复制业务状态机 |
| 画面过小导致信息不可读 | 每个镜头只强调一个信息目标，使用镜头推进而非额外说明卡片 |
| 转场过多破坏产品气质 | 限定转场类型和时长，在视觉样片阶段先锁定运动语言 |
| 旁白决定过晚导致节奏返工 | 第一轮先锁无旁白叙事；决定加入旁白后再冻结最终时间线 |

## 14. 阶段结束条件

满足以下条件后，本轮演示视频制作才算完成：

1. 分镜中的所有场景均已完成并通过逐帧检查。
2. 核心学习闭环在 55–65 秒内连续、清晰地表达。
3. 无旁白样片经过确认；若决定加入旁白，最终声音版本也已通过验收。
4. 最终 MP4、封面帧和结果文档已经留档。
5. `admin/` 和 `video/` 均可在新的环境中按文档命令启动。
6. TypeScript、原型生产构建和 Remotion 最终渲染全部通过。
