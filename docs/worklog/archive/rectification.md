## 一、先澄清并统一产品方向

这是一个供用户日常使用的知识管理与学习 Agent 产品，不是品牌官网、概念落地页或作品展示页。

核心信息架构为：

- 今日：聚焦当前最值得完成的一项学习行动
- 学习：以知识地图为核心，支持探索关系、查看节点和继续学习
- 知识库：管理用户拥有的资料、笔记与派生知识
- Agent：全局可进入的智能协作入口，但不是唯一产品界面

全局设计原则：

1. 核心功能页不承担品牌宣言，只承担定位、操作与反馈。
2. 禁止在每个页面重复使用“大栏目名 + 大 Slogan + 大段留白 + 功能预览”的落地页结构。
3. 大 Slogan 只允许出现在官网、首次引导和必要的空状态。
4. “编辑式极简”不等于 Markdown 文档式排版；需要通过容器、空间层级、内容密度和交互表面建立产品感。
5. 卡片不是完全禁止，而是按信息语义使用：
   - 有明确边界的任务、状态和变化适合使用卡片；
   - 地图、画布等连续探索空间不应被套进普通卡片；
   - 避免把所有文字分别装进一组同质化白色圆角矩形。
6. 玻璃效果集中用于底部导航、Agent 入口、浮层和抽屉；普通正文和知识列表以实体表面为主。
7. 删除正式页面中的“原型”“模拟数据”等开发提示文字。
8. 保留移动端优先、编辑式极简、暖白背景、低饱和点缀色、建筑式局部玻璃的整体视觉语言。

请先定位文档中与这些原则冲突的旧描述并修改，再按照修订后的文档调整代码。不要只改代码而保留相互冲突的规范。

## 二、重构“今日”页面

当前页面过于依赖字号、分割线和留白，像排版后的 Markdown 文档。请改成“焦点任务卡统领、少量变化卡补充”的行动页面。

页面结构：

### 1. 顶部轻量信息

只保留日期和一句简短引导，例如：

- 7 月 22 日，周三
- 今天，我们只完成一件事。

不要再使用占据首屏的大标题或宣传式 Slogan。

### 2. 今日焦点任务卡

把“下一步建议”升级为首屏视觉中心，一张大型主卡承载：

- 今日重点
- 预计用时
- 任务标题
- 推荐原因
- 所属主题/章节
- 明确的“开始学习”主操作
- 可选的极淡知识节点、关系线或学科色块作为空间化背景

示例内容：

今日重点｜约 8 分钟
理解监督学习与无监督学习
它们是后续两个主题共同依赖的基础概念。
机器学习 · 第三章
[开始学习 →]

视觉要求：

- 卡片有明确体积感和内容边界；
- 使用暖灰或极淡主题色表面；
- 约 24–28px 圆角；
- 轻边框、弱阴影或克制的局部玻璃；
- 操作按钮稳定地位于卡片底部；
- 不要退化成白底文字容器，也不要做成常见 SaaS 仪表盘。

页面只能有一个视觉中心：今日任务。不要同时保留“理念大标题”和“建议卡”两个中心。

### 3. 近期变化

将平面列表改为低权重的横向变化卡：

- 显示主题、变化类型、时间和查看入口；
- 可让后一张卡片部分露出，暗示横向浏览；
- 高度和视觉权重明显低于主任务卡；
- 使用低饱和学科色进行轻量区分；
- 不使用大按钮或强阴影。

底部必须为悬浮导航预留足够安全区，内容不能被导航遮挡。

## 三、重构“学习地图”页面

当前页面把知识地图做成了“介绍知识地图的落地页”。请删除无操作价值的大 Slogan，让地图成为页面主体。

删除或替换：

- “让知识在关系中形成轮廓”等大宣言；
- “原型 · 模拟数据”；
- 占据大量空间的编辑式说明行；
- 不符合地图操作习惯的大胶囊控件。

页面顶部改为紧凑工具栏，例如：

学习地图                         搜索  ＋
12 个主题 · 3 个待复习

可在下方设置紧凑筛选：

全部｜学习中｜待复习｜已掌握

地图应从工具栏下方延伸到底部导航上方，占据除导航外约 75%–80% 的屏幕。地图本身是主交互画布，不要再将它包装成一张普通白色卡片。

地图视觉层级：

- 当前焦点：最大、对比最强、主要连线加深；
- 一度关联：中等尺寸、低饱和色、关系清晰；
- 背景节点：尺寸更小、透明度更低，接近或拖动时逐渐显现。

完善地图的平移、缩放、复位/定位和节点选择反馈。图例改为可展开的小控件，不要长期占据画布。

点击节点后，从底部出现约 30% 高度的浮动信息面板，显示：

- 节点名称与简要解释
- 掌握状态
- 关联节点
- 继续学习
- 查看相关资料

未选择节点时不显示焦点说明。自由 Agent 问答本身不得自动更新学习状态；只有明确的学习行为和学习证据才能更新节点状态。

## 四、同步检查其他页面

检查知识库、Agent 抽屉和其他已实现页面是否也套用了“大 Slogan + 大留白”的落地页模板。

如存在，请按页面任务纠正：

- 知识库应优先展示搜索、分类、资料状态和内容管理；
- Agent 应体现上下文协作与引用，而不是聊天宣传页；
- 标题只负责定位，不负责反复表达品牌理念；
- 各页面可以采用不同的信息承载方式，不要求统一套卡片或统一套大标题；
- 页面统一来自字体、颜色、间距、圆角、玻璃、底部导航和动效规则，而不是相同版式。

## 五、工程要求

1. 先阅读现有代码和文档，不要凭文件名猜测结构。
2. 列出需要修改的文档、页面、组件、样式和模拟数据。
3. 优先复用和修正现有设计 Token 与基础组件，避免页面内散落硬编码。
4. 将主任务卡、变化卡、地图工具栏、地图节点状态和节点详情面板抽成合理组件。
5. 不接入后端，继续使用模拟数据，但数据结构应便于以后替换为真实接口。
6. 不引入与任务无关的新框架，也不要扩大产品范围。
7. 保持移动端优先，同时保证常见手机宽度下无横向溢出、遮挡和不可点击区域。
8. 动效应克制，服务于层级、拖拽、吸附、展开和状态变化。
9. 修改后运行项目并检查构建、类型检查和现有测试。
10. 如仓库实现与 PRD 存在冲突，以本次方向为准，并同步修改 PRD/UI 规范，不得保留两套相互矛盾的口径。

## 六、验收标准

完成后应满足：

- “今日”首屏的视觉中心是唯一一张焦点任务卡，而不是大 Slogan；
- “近期变化”由低权重小卡承载，且不会被底部导航遮挡；
- “学习地图”进入页面后即可直接探索，地图占据绝大部分可用空间；
- 地图不是卡片预览，也没有宣传式大标题；
- 节点选择通过底部面板反馈；
- 其他核心功能页不再重复落地页构图；
- 卡片被用于建立信息边界和主次，而不是被全面禁止或无差别滥用；
- 文档、设计规范和代码对产品方向的描述完全一致；
- 项目能够正常启动和构建。
