**状态：** 已过期
**归档日期：** 2026-07-22
**原状态：** 已完成（R0–R5）
**适用范围：** `admin/` 的 P0 移动端高保真前端原型。继续使用模拟数据，不接入后端，不修改 `entry/`。

## 1. 重构目标

将当前原型从“移动尺寸上的网页页面”重构为供用户日常进入、单手操作和连续返回的移动端产品界面。

使用场景是：用户在课间、通勤或一次短暂学习间隙打开 App，快速确认当前任务、探索知识关系或查看自己的资料。界面应优先保证目的地稳定、内容可扫读、操作可达和上下文可恢复，而不是通过大标题、材质或动效吸引停留。

## 2. 已确认的方向

1. 产品注册为 **mobile product UI**，不是品牌官网、概念页或作品展示页。
2. 一级目的地固定为“今日｜学习｜知识库”，Agent 是独立全局操作，不占用第四个 Tab。
3. 页面标题只负责定位；大 Slogan 仅用于首次引导、必要空状态或外部官网。
4. 卡片只承担任务、状态与变化等有明确边界的信息，不作为通用文字容器。
5. 地图是连续探索画布，不包装成普通内容卡。
6. Agent 保留约 75% / 全屏抽屉；节点详情保持约 30% 的轻量信息面板。
7. 所有正式页面删除“原型”“模拟数据”等开发提示，模拟属性只保留在代码边界与验收记录中。

## 3. 材质策略：局部采用液态玻璃

### 3.1 材质层级

| 层级 | 表面策略 | 允许组件 |
| --- | --- | --- |
| 内容层 | 稳定实体暖白或暖灰，优先可读性 | 今日任务卡、变化卡、知识库列表、地图节点、节点信息面板 |
| 控制层 | 轻薄磨砂玻璃，可试验极弱液态边缘和高光 | 底部导航、Agent 圆形入口、地图缩放/定位、图例与少量筛选控制 |
| 浮层 | 厚磨砂或近白实体，强调遮挡关系 | Agent 抽屉、底部菜单、来源预览 |
| 决策层 | 炭黑或近白实体 | 主操作、确认、发送与高风险操作 |

### 3.2 液态玻璃的使用边界

- 只允许用于控制层的边缘折射、内高光和按压反馈，不作为页面背景、内容卡片或地图视觉主题。
- 同一屏最多保留两组明显玻璃实体，避免导航、筛选、卡片、节点和按钮同时发亮。
- 液态效果必须在静态时几乎不可察觉；仅在按压、吸附、抽屉抬升或导航状态切换时提供层级反馈。
- 任务卡、列表、正文、知识节点和普通信息面板禁止使用折射、色散或持续形变。
- 降级优先级高于视觉效果：不支持滤镜、系统减少透明度、低性能或滚动/拖拽帧率不足时，回退为半透明实体表面。

### 3.3 依赖策略

不直接引入完整液态玻璃组件库作为页面基础设施。先建立本地 `GlassSurface` 语义组件：

- 基线实现：CSS 的半透明背景、`backdrop-filter`、极细边缘和克制阴影；
- 适配层：如需实验，可在 `GlassSurface` 内局部接入 `@liquidglass/react` 或参考 `liquid-glass-react` 的实现；
- 回退层：实体暖白背景、细边框和阴影，保持尺寸、点击区域与层级不变；
- 业务页面只引用 `GlassSurface`，不直接依赖任何外部玻璃库的 Props。

外部参考仅用于验证，不在本轮直接安装：

- [TDesign Mobile React](https://github.com/Tencent/tdesign)：移动端控件尺寸、列表和弹层交互参考；
- [Ant Design Mobile](https://mobile.ant.design/)：输入、选择和弹层的可访问性参考；
- [liquid-glass-react](https://github.com/rdev/liquid-glass-react) 与 [@liquidglass/react](https://www.npmjs.com/package/%40liquidglass/react)：局部材质实验参考；
- Ionic 与 Framework7 不引入，它们会重塑当前应用壳和路由模型。

## 4. 组件重构边界

| 组件 | 职责 | 材质 |
| --- | --- | --- |
| `AppShell` | 安全区、页面状态恢复、全局浮层层级 | 无 |
| `MobileTopBar` | 页面定位、搜索、更多操作 | 实体或无容器 |
| `BottomNavigation` | 三个同级目的地切换 | 轻薄玻璃 |
| `AgentLauncher` | 打开 Agent 的独立操作 | 轻薄玻璃 |
| `GlassSurface` | 控制层、浮层的统一材质与降级 | 局部液态玻璃可选 |
| `TaskFocusCard` | 今日唯一焦点任务 | 暖灰实体 |
| `ChangeRail` / `ChangeCard` | 低权重近期变化 | 实体 |
| `MapToolbar` / `MapFilterBar` | 地图缩放、定位、图层和筛选 | 小体积玻璃 |
| `MapCanvas` | 平移、缩放、惯性、弱吸附和节点层级 | 连续画布 |
| `NodeInfoPanel` | 约 30% 的节点概要与出口 | 稳定实体或厚磨砂 |
| `AgentSheet` | 75% / 全屏上下文协作与输入 | 厚磨砂到近白实体 |

## 5. 页面重构骨架

### 5.1 今日

`日期 + 一句引导 → 焦点任务卡 → 横向近期变化`

- 焦点任务卡是唯一视觉中心，按钮固定在卡片底部；
- 近期变化用于告知资料、关系或学习证据的新增，不抢夺主任务；
- 页面不再出现宣言式标题、指标矩阵或功能导览。

### 5.2 学习地图

`紧凑顶部工具栏 → 范围信息 → 状态筛选 → 连续地图画布 → 可展开图例`

- 地图从工具栏下方延展至底部导航上方；
- 节点状态独立于知识类别颜色；
- 点击节点后显示 `NodeInfoPanel`，而非打开与 Agent 同规格的大抽屉；
- 图例、缩放与定位是小型工具，不长期占据画布。

### 5.3 知识库

`顶栏搜索/范围 → 筛选 → 资料列表 → 文件状态与元数据`

- 优先解决查找、分类、处理状态和来源管理；
- 使用列表和稳定列对齐，不复用今日任务卡布局；
- 上传是克制入口，不成为页面主视觉。

### 5.4 Agent

`可移除上下文 → 对话/建议问题 → 固定输入`

- Agent 是协作工具，不承担产品宣言；
- 仅 Agent 使用 75% 与全屏的拖拽、阻力和吸附；
- 玻璃随高度增加而降低透明度，全屏时转为近白实体阅读面。

## 6. 实施顺序

1. **R0，结构止损**：删除落地页式标题与开发提示，冻结页面结构，保留现有可用交互。
2. **R1，基础层**：抽取语义 Token、`AppShell`、`MobileTopBar`、`GlassSurface`，定义实体与玻璃两套表面状态及降级。
3. **R2，目的地重构**：按“今日 → 学习地图 → 知识库”顺序替换页面骨架，确保每页拥有不同信息承载方式。
4. **R3，空间交互**：完成地图状态层级、节点信息面板和 Agent 抽屉的手势归属，避免两种面板互相竞争。
5. **R4，液态玻璃验证**：仅在导航、Agent 入口和地图工具做 A/B 截图对比；若可读性、性能或降级不达标，保留标准磨砂实现。
6. **R5，验收**：在常见移动宽度验证安全区、键盘避让、横向滚动、减少动态/透明度、触控尺寸、页面状态恢复和生产构建。

## 7. ArkUI 迁移约束

- 设计 Token、语义组件名、状态机和模拟数据结构必须与 Web 渲染实现分离。
- 页面代码不得将外部 Web 组件库的类型、DOM 事件或样式类名泄漏到业务数据与页面状态中。
- 手势对外以“平移、缩放、定位、打开/关闭、吸附到状态”描述；Web 与 ArkUI 分别实现具体事件和动画。
- `GlassSurface` 的视觉规范只描述透明度、模糊、边缘与降级规则；ArkUI 端按同一语义映射为原生材质，不复制 CSS 滤镜实现。
- 每个语义组件至少保留默认、按压/激活、选中、禁用、减少动态和不支持透明度的状态，以便一对一迁移与验收。

## 8. 验收标准

- 任一页面去除玻璃效果后，信息层级和操作优先级仍然成立。
- 液态玻璃不出现在内容卡、正文、地图节点或列表行。
- 控制层在不支持滤镜时仍保持可读、可点击、尺寸稳定。
- 三个导航目的地长期固定，Agent 保持独立操作语义。
- 今日、学习、知识库和 Agent 使用不同但一致的移动端信息骨架，不再共享落地页模板。
- Web 原型的 Token、组件职责、状态和数据结构可映射到 ArkUI，不依赖完整 Web UI 框架。
