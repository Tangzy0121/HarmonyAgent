# HarmonyAgent 多格式输入（Markdown / DOCX）设计规格（草案，待评审）

**状态：** 已获用户批准（2026-08-17；待拍板 4 项全部按草案建议定稿：多格式单文件先行、字符上限 45,000、引入 mammoth、虚拟页 1,500 字符 ±10% 段落截断）  
**日期：** 2026-08-17  
**适用范围：** HarmonyAgent 第二轮能力（Sprint C 第一阶段）  
**前置：** 互动学习书 MVP 规格（2026-08-09）；**本规格通过后，MVP 规格 §3.1 与 §3.3 按下文 §2 修订**

## 1. 设计结论

把学习书的输入从「仅文本型 PDF」扩展到 **Markdown 与 DOCX**，仍坚持**一份文件生成一本书**。多文件合书本阶段不做，留作后续独立阶段。最大的设计点是：md/docx 没有页码，citation 的「原文可核对 + 位置可跳转」语义通过**服务端虚拟分页**保持——解析时按固定字符窗口切成虚拟页，页码语义、子串硬校验、prompt 预算、锚点跳转全部沿用 PDF 链路，不改一章生成管线。

## 2. 对 MVP 规格的修订（本规格通过后生效）

- §3.1 输入范围修订为：「每次只处理**一个文件**；支持文本型 PDF、Markdown（.md/.markdown）、DOCX（.docx）。PDF 上限 30 页或 20 MB；md/docx 按解析后正文字符数 ≤ 60,000 字（约等于 30 页）且文件 ≤ 20 MB。」
- §3.3 明确排除中删除「PPT、Word」改为「PPT、扫描件/OCR、加密文件」；「多文件合成一本书」**仍然排除**。

## 3. 范围

### 3.1 包含

- 上传入口接受 .md/.markdown/.docx（MIME + 扩展名双校验）；超出上限在选择后、上传前明确阻止（与 PDF 同口径）。
- 解析层：md 直接读 UTF-8 文本（去 frontmatter）；docx 用 **mammoth**（MIT，纯文本抽取，不保留样式）。统一产出 `ParsedDocument { pageCount, pages[] }`——按**虚拟分页**（§4）。
- citation、目录提案、渐进生成、笔记、导出、学习者模型全部对新格式生效（虚拟页码对上层透明）。
- 上传 Sheet 支持范围文案、错误码、删除说明同步更新。

### 3.2 明确排除

- 多文件合书；
- docx 内嵌图片/表格结构还原（mammoth 纯文本，图片丢弃并在 UI 说明）；
- PPT、XLSX、扫描件、OCR、加密/损坏文件；
- 虚拟页码与物理页码的互认（同一书内自洽即可）。

## 4. 虚拟分页（核心设计）

- 解析后全文按 **1,500 字符/页** 切分为虚拟页（中英文皆按字符数；与 PDF 一页正文体量同量级）。
- `pageCount = ceil(总字符数 / 1500)`，上限 30 页等效即 45,000 字……与 §2 的 60,000 不一致——**待拍板 #2**，建议统一为 45,000 字（30 虚拟页）。
- 分页在**段落边界**就近截断（±10%），避免句子被劈开；分页结果随文档持久化，生成与导出引用同一虚拟页码。
- citation 校验沿用现有规则：摘录去空白子串命中对应虚拟页文本、`pageRange` 落在该页——代码零改动，只是「页」的来源不同。
- docx 解析失败 → `docx_unreadable`；md 全文 <200 字 → `doc_no_text`（复用 PDF 的五错误码风格）。

## 5. 工程影响

| 模块 | 动作 |
| --- | --- |
| `server/src/documents/` | 新增 `markdownParser.ts` / `docxParser.ts`（共用 `virtualPages.ts`）；`pdfParser.ts` 不动 |
| `server/src/routes/documents.ts` | 接受新 Content-Type/扩展名，按格式分发解析器；20MB raw 限制沿用 |
| `server/package.json` | 新增依赖 `mammoth`（MIT） |
| `admin/src/components/book/UploadBookSheet.tsx` | 接受扩展名、支持范围与隐私文案更新 |
| `admin/src/services/bookApi.ts` | uploadDocument 的格式参数 |
| 导出/地图/今日/学习者模型 | 零改动（虚拟页码透明） |

## 6. 验收标准

1. 上传一份 ~4 万字的 .md → 解析出 ≤30 虚拟页，页边界不断句；
2. 上传一份真实 .docx（含图片）→ 纯文本解析成功，UI 说明图片不保留；
3. md 生成的书中 citation 摘录可核对到对应虚拟页文本（子串硬校验通过）；
4. 超限文件（>45,000 字或 >20MB）在选择后上传前被阻止并说明原因；
5. PDF 链路回归：既有 388 项 server 测试全绿；
6. 加密/损坏 docx → 稳定错误码 `docx_unreadable`。
