# 视觉设计规范

## 1. 文档目的

本文档用于明确知识管理 Agent 的整体视觉气质、布局原则、排版与色彩、组件材质、空间层级和动态语言，并作为后续高保真原型、设计系统、前端实现和视觉验收的共同依据。

本文档承接《信息架构与页面结构.md》与《用户旅程.md》。它不重新定义页面职责，而是回答以下问题：

1. 产品应呈现怎样的气质；
2. 各页面如何在保持统一的同时形成不同节奏；
3. 哪些内容保持平面，哪些组件使用磨砂玻璃和空间体积；
4. 自由拖拽、阻力、惯性与自动吸附如何形成统一交互语言；
5. 后续设计和开发应遵循哪些边界，避免落入常见的 AI 产品或 SaaS 视觉套路。

文中标记为“首版建议”的数值用于快速建立原型，不代表已经完成视觉验证。最终数值应结合真机观感、可读性、性能和交互测试调整。

---

## 2. 核心视觉命题

### 2.1 产品气质

> **安静、克制、聪明，具有空间感的编辑式极简主义。**

产品不是临时聊天工具、打卡学习软件或文件管理器，而是一个能够逐渐形成个人形状的长期知识系统。因此，界面需要同时具备：

- 极简主义的克制；
- 编辑设计的排版秩序；
- 数字产品的精密与清晰；
- 轻微的人文温度；
- 由交互而非装饰产生的生命感；
- 能够表现知识关系的连续空间。

### 2.2 核心形式语言

> **以平面排版建立秩序，以局部磨砂玻璃表达悬浮层级，以阻力与吸附表达隐性秩序。**

静态界面应当安静、稳定；动态界面在用户触发探索、聚焦、展开和归位时才表现生命感。设计感主要来自布局、比例、留白、遮挡关系和运动，而不是依靠纹理、渐变或装饰图形。

### 2.3 核心动态隐喻

> **自由探索发生在连续空间中，关键操作最终吸附到离散秩序上。界面允许偏离，但始终帮助用户稳定地落下来。**

这套隐喻与产品的知识管理逻辑一致：思考可以发散，知识最终会被整理进结构。

## 3. 设计原则

### 3.1 内容保持平面，控制与浮层获得体积

- 今日内容、学习正文、知识库列表直接落在页面画布上；
- 导航、筛选器、对话入口等全局控制可以轻微悬浮；
- Agent 抽屉和节点抽屉使用更明确的空间体积；
- 关键确认按钮采用实体黑白表面，不使用玻璃；
- 不为每条信息套卡片，不用组件数量制造层级。

### 3.2 理性网格作为骨架，编辑式布局形成局部张力

- 高频页面保持稳定对齐、明确节奏和可预期位置；
- 关键时刻允许使用大留白、局部偏置、字号反差和不对称构图；
- 编辑式张力用于突出焦点，不用于打乱阅读顺序；
- 同一任务流中的返回、确认和导航位置必须稳定。

### 3.3 黑白建立秩序，颜色只传递差异

- 主界面以近白、炭黑和中性灰构成；
- 低饱和色用于知识类别、关系、引用、焦点和必要状态；
- 颜色不承担普通按钮装饰，不大面积铺设品牌渐变；
- 任何重要信息不能只依赖颜色表达。

### 3.4 静态界面安静，动态界面有生命

- 没有用户操作时，不让大量元素持续漂浮、发光或形变；
- 动效用于解释对象从哪里来、去往哪里、与什么发生关系；
- 地图、抽屉与全局控制可以表现物理感；
- 正文、列表和普通信息反馈保持快速、克制。

### 3.5 柔和，但不软萌

- 字体避免锋利和过度装饰；
- 圆角具有明确等级，不扩散到所有内容；
- 回弹强调阻尼与重量，不做软糖式弹跳；
- 图标可以带圆角，但不采用卡通、拟人或玩具化语言。

### 3.6 逐步揭示，而非同时展示

- 页面先展示当前最重要的内容；
- 复杂关系通过聚焦、抽屉、展开和缩放逐层出现；
- 地图负责结构，抽屉负责概要与导航，知识库负责资料正文；
- 视觉层级必须延续信息架构边界，不能因为追求丰富而重新混合功能。

## 4. 布局系统

### 4.1 总体布局性格

采用“理性网格 + 编辑式局部张力”的混合布局：

| 场景 | 布局策略 | 目的 |
|---|---|---|
| 今日、知识库、设置 | 稳定网格、清晰对齐 | 支持长期高频使用 |
| 深入学习、资料正文 | 收窄阅读宽度、稳定垂直节奏 | 保证专注与可读性 |
| 知识地图 | 开放画布、局部焦点 | 支持空间探索与关系理解 |
| 首次空白、学习完成、成果确认 | 大留白、偏置构图、比例反差 | 形成关键体验时刻 |
| Agent 与节点抽屉 | 前景实体 + 后方保留上下文 | 维持空间连续性 |

### 4.2 网格建议

首版以移动端为主要设计基准：

- 基础间距单位：`4px`；
- 常用间距序列：`8 / 12 / 16 / 24 / 32 / 48 / 64px`；
- 页面左右安全边距：首版建议 `20px`，大屏手机可提高至 `24px`；
- 移动端采用 4 栏概念网格，普通内容通常跨满 4 栏；
- 平板采用 8 栏，桌面采用 12 栏；
- 正文阅读区域不随屏幕无限变宽，应保持舒适行长；
- 地图画布不受正文最大宽度限制。

网格服务于对齐关系，不要求所有元素都填满栏宽。标题、数字、局部图形和状态标记可以有控制地偏离网格，但核心操作和主要文本需要回到稳定基线。

### 4.3 留白规则

- 留白是内容层级的一部分，不是待填充区域；
- 同级内容之间使用固定节奏，章节间距显著大于段落间距；
- “今日”的首要行动周围保留最大留白；
- 知识库允许更高信息密度，但依靠行距、分隔线和列对齐保持呼吸感；
- 地图中的空白代表知识结构中的距离，不应被装饰元素填满。

### 4.4 不对称的使用边界

允许：

- 大标题与内容块形成非居中关系；
- 局部数字、日期或状态从网格中轻微越界；
- 学习完成时，用偏置的小型地图缩略图和成果文字形成张力；
- 地图聚焦后，将目标节点移动到适合抽屉展开的视觉位置，而非机械居中。

不允许：

- 破坏自然阅读顺序；
- 让高频按钮在不同页面随机换位；
- 为追求设计感牺牲可点击范围；
- 让正文段落形成难以追踪的多列跳读。

## 5. 字体与排版

### 5.1 字体选择

首版建议：

- 中文及正文：**Noto Sans SC / 思源黑体**；
- 英文与数字：默认沿用中文字体；需要更精细的拉丁字母和数字表现时搭配 **Inter**；
- 系统回退：`PingFang SC`、`Microsoft YaHei`、`sans-serif`。

建议字体栈：

```css
font-family:
  "Noto Sans SC",
  "Source Han Sans SC",
  "PingFang SC",
  "Microsoft YaHei",
  sans-serif;
```

Noto Sans CJK 与 Inter 均使用 SIL Open Font License 1.1，可作为产品嵌入字体的优先候选。正式发布前仍需记录实际使用的字体版本、字库裁剪方式与许可证文件。

### 5.2 字重原则

主要使用：

- `400`：正文、说明、长文本；
- `500`：标签、按钮、强调内容；
- `600`：页面标题、关键数字和少量强层级。

尽量不使用 `700` 及以上字重。标题主要通过字号、位置和留白形成层级，而不是依靠极粗字重制造冲击。

### 5.3 首版排版层级

| 层级 | 移动端建议 | 字重 | 用途 |
|---|---:|---:|---|
| Display | 36–44px / 1.15 | 500–600 | 首次空白、成果确认等少量关键时刻 |
| H1 | 28–32px / 1.25 | 600 | 页面主标题 |
| H2 | 22–24px / 1.35 | 500–600 | 大区块标题 |
| H3 | 18–20px / 1.45 | 500 | 内容小节标题 |
| Body | 16px / 1.6–1.75 | 400 | 正文、学习内容、对话 |
| Label | 14px / 1.45 | 500 | 控件、标签、列表辅助信息 |
| Caption | 12–13px / 1.45 | 400–500 | 来源、时间、状态补充 |

中文正文不宜过小或过密。知识库可以提高信息密度，但不能通过压缩至 12–13px 正文来实现。

### 5.4 数字与状态

- 日期、学习次数、节点数量可以使用等宽数字特性；
- 大数字只出现在确有信息价值的地方，不作为装饰；
- 状态层级优先依靠文字、位置和对比度，颜色只做辅助；
- 英文大写只用于极少量短标签，不用于长标题。

## 6. 色彩系统

### 6.1 色彩策略

> **以黑白秩序建立界面，以低饱和色表达知识差异。**

“黑白”不等于大面积使用纯黑 `#000000` 与纯白 `#FFFFFF`。大面积底色和文字应略微柔化，以降低长时间阅读的刺激感。

### 6.2 中性色首版建议

| Token | 建议色值 | 用途 |
|---|---|---|
| `bg.canvas` | `#F5F4F0` | 页面主背景，略带温度的近白 |
| `bg.surface` | `#FBFAF7` | 抽屉全屏、阅读表面、实体浮层 |
| `text.primary` | `#1B1B19` | 主要文字与深色按钮 |
| `text.secondary` | `#6F6D68` | 次级信息 |
| `text.tertiary` | `#99968F` | 弱提示、时间、非关键状态 |
| `line.default` | `#DCD9D2` | 分隔线、输入边界 |
| `line.strong` | `#C7C3BA` | 选中边界与强调分隔 |
| `overlay.scrim` | `rgba(18,18,16,0.24)` | 抽屉打开后的背景遮罩 |

实际落地时需要进行 WCAG 对比度检查。低对比灰色不能用于关键说明、正文或唯一状态提示。

### 6.3 低饱和点缀色首版建议

| 色组 | 建议色值 | 初步语义 |
|---|---|---|
| 雾蓝 | `#7E8FA2` | 方法、技术、结构关系 |
| 鼠尾草绿 | `#87958A` | 自然、生命、实践类知识 |
| 灰紫 | `#8E879A` | 理论、抽象与人文类知识 |
| 黏土红 | `#A27F73` | 案例、历史、警示或当前活动 |
| 暗赭黄 | `#A18E65` | 应用、经验、待确认关系 |

这些语义只是首版映射，应结合真实知识类别数量和地图辨识度验证。点缀色不建议直接作为小字号正文颜色；需要承载文字时，应使用更深的可访问性变体。

### 6.4 颜色使用比例

- 中性黑白灰：约占整体视觉的 85%–95%；
- 低饱和类别色：约占 5%–15%；
- 单一画面中避免所有类别色同时高强度出现；
- 地图是颜色使用最丰富的区域，正文页面最克制；
- 主按钮默认使用炭黑或近白实体色，不跟随知识类别变色。

### 6.5 颜色不承担的职责

- 不用蓝紫渐变代表“AI”；
- 不用大面积渐变背景制造科技感；
- 不用红绿二元色独立表达成功与失败；
- 不用彩色填充区分所有普通卡片或按钮；
- 不将学习状态与知识类别混为同一套颜色。

## 7. 材质与空间层级

### 7.1 四层材质系统

| 层级 | 视觉处理 | 适用组件 |
|---|---|---|
| 内容层 | 平面、无独立卡片，依靠排版和留白分区 | 今日内容、学习正文、知识库列表 |
| 控制层 | 轻薄磨砂玻璃，小体积、轻悬浮 | 底部导航胶囊、对话入口、筛选器 |
| 浮层 | 更厚、更不透明的磨砂表面 | Agent 抽屉、节点抽屉、底部菜单 |
| 决策层 | 炭黑或近白实体，不使用玻璃 | 主按钮、确认操作、关键状态反馈 |

玻璃是一种空间材料，只用于表达覆盖、控制和层级，不是通用内容容器。

### 7.2 玻璃质感

目标是安静、偏建筑感的磨砂表面，而不是彩色霓虹背景上的通透玻璃。

- 玻璃偏乳白或烟灰，透明度适中；
- 背景只能被模糊感知，不能清晰穿透；
- 边缘保留极细的内高光与低对比描边；
- 阴影宽而淡，用于表现距离，不制造悬浮卡片感；
- 低饱和颜色可以在玻璃下方轻微透出；
- 文字区域需要稳定底色，不能因背景变化影响可读性。

首版可从以下参数开始验证：

| 材质 | 背景建议 | 模糊建议 | 其他 |
|---|---|---|---|
| 轻薄玻璃 | `rgba(250,249,246,0.62)` | `16–22px` | 极细亮边，淡阴影 |
| 厚玻璃 | `rgba(250,249,246,0.80)` | `24–32px` | 更明确顶部边缘和遮挡 |
| 烟灰玻璃 | `rgba(35,35,32,0.56)` | `20–28px` | 仅用于深色模式或特殊浮层 |

应根据设备性能提供降级方案：不支持或不适合实时模糊时，使用接近最终观感的半透明实体色，而不是牺牲滚动与拖拽流畅度。

### 7.3 体积的构成

空间体积由四部分共同形成：

1. **遮挡关系**：抽屉覆盖地图，导航浮在画布上方；
2. **边缘厚度**：外轮廓与内高光形成薄截面；
3. **背景折射**：下方颜色经过模糊后产生轻微晕染；
4. **进入动效**：组件从较低层级抬升并吸附，而不是简单淡入。

阴影只负责补充距离感，不能单独承担体积。

### 7.4 阴影原则

- 使用低透明度、较大扩散范围的中性阴影；
- 避免硬边、黑色重阴影和多层彩色光晕；
- 内容列表、正文区和普通按钮默认无阴影；
- 同一页面最多保留少数几个明显悬浮层级。

## 8. 形态、圆角与边界

### 8.1 圆角等级

| 等级 | 首版建议 | 适用对象 |
|---|---:|---|
| 完整圆形 | `50%` | 对话入口、状态点 |
| 胶囊 | `999px` | 底部导航、少量分段控制 |
| 大圆角 | `24–28px` | Agent 与节点抽屉顶部 |
| 中圆角 | `12–16px` | 按钮、输入框、确认面板 |
| 小圆角 | `6–10px` | 标签、小型筛选器、缩略图 |
| 无圆角 | `0` | 正文、列表、普通信息区 |

“圆”主要属于全局控制和交互入口；知识内容本身保持平面和编辑式。

### 8.2 边界表达

边界表达的优先顺序：

1. 留白；
2. 对齐关系；
3. 轻微底色差；
4. 细分隔线；
5. 玻璃边缘；
6. 阴影。

除表单校验和强选择状态外，不使用粗边框。避免同时对一个组件使用底色、边框、阴影和大圆角四重强调。

### 8.3 图标

- 使用中性、圆角适度的线性图标；
- 线宽在同一尺寸下保持一致；
- 图标与文字共同出现时，图标不承担重复装饰；
- Agent 不使用机器人头像、星光、魔法棒或闪烁粒子；
- 当前项主要通过文字对比和位置标记表达，不依赖图标填充动画。

## 9. 动态语言

### 9.1 总原则

> **有惯性地离开，有阻力地接近，有判断地归位。**

产品追求的不是“弹”，而是阻尼；不是“炫”，而是归位。运动必须让用户感知对象的重量、边界、来源与落点。

### 9.2 三种运动强度

| 场景 | 运动特征 | 首版时长参考 |
|---|---|---:|
| 普通内容 | 快速、克制，小幅位移或透明度变化 | 120–200ms |
| 导航与控件 | 精确吸附、轻微按压和回弹 | 180–260ms |
| 地图与抽屉 | 惯性、阻力、重量和空间位移 | 280–480ms 或物理弹簧 |

物理交互优先根据速度、距离和边界计算，不应强行使用同一固定时长。

### 9.3 阻力

- 拖拽开始前设置很小的意图阈值，减少误触；
- 手势过程中保持跟手，不用明显延迟伪造重量；
- 接近不可继续移动的边界时逐渐增加阻力；
- 内容滚动与抽屉拖拽应明确判定手势归属；
- 阻力不能强到让用户误以为界面卡顿或操作无效。

### 9.4 自动吸附

- 吸附点数量保持克制，只保留清晰、稳定的落点；
- 落点由当前位置与释放速度共同决定；
- 接近吸附范围时逐渐受力，不突然跳变；
- 用户快速、明确的手势可以跨过中间吸附点；
- 关闭后恢复用户此前视角、滚动位置或抽屉高度，而不是机械复位。

### 9.5 知识地图

- 自由拖拽和缩放具有轻微重量感；
- 松手后保留短暂惯性，但快速衰减；
- 合理缩放级别、主题簇和关键节点可以形成弱吸附；
- 点击节点后，地图整体平移，将节点带到适合抽屉展开的焦点区；
- 一阶关系随聚焦渐进高亮，其他内容降低存在感但不立即消失；
- 关闭抽屉后恢复此前视角；
- 不让所有节点持续漂浮，不使用无意义粒子流。

### 9.6 上拉抽屉

抽屉的主要吸附状态：

1. 关闭；
2. 默认约 75%；
3. 全屏。

交互规则：

- 起始拖动越过轻微阈值后才接管手势；
- 拖动跟手，接近边界时出现渐进阻力；
- 释放时结合位置和速度选择落点；
- 接近关闭边界时增加适量阻力，降低误关概率；
- 明确快速下甩仍可直接关闭；
- 上拉至全屏时，磨砂逐渐转为接近实体的近白表面；
- 输入框聚焦、键盘弹出后，Agent 抽屉自动扩展至接近全屏；键盘收起后恢复用户此前高度。

### 9.7 底部导航与对话入口

- 当前项标记沿导航胶囊内部移动并吸附到目标；
- 不在经过其他项时逐个停顿；
- 对话圆形入口按下时轻微下沉，松开后恢复并带出抽屉；
- 对话入口与导航胶囊是两个相邻但独立的空间实体；
- 呼吸感仅通过极轻微的高光或体积变化表现，不做外发光。

### 9.8 深入学习与完成

- 学习阶段完成后，当前内容向上收束，下一阶段自然接入；
- 引用、解释和练习关闭时回到原锚点；
- 完成后，学习过程归拢为一条学习证据，并附着到知识节点；
- S10 安排下一步后，日期或行动轻微归位，界面随即安静下来；
- 不使用烟花、金币、奖章或夸张庆祝动画。

### 9.9 减少动态模式

系统开启“减少动态效果”时：

- 取消大范围视差、惯性和弹簧回弹；
- 地图聚焦改为短距离平移或直接切换；
- 抽屉仍保留清晰的开合与吸附状态，但缩短运动路径；
- 不影响功能状态、焦点管理和手势可达性。

## 10. 核心组件规范

### 10.1 底部导航胶囊

- 内容：今日｜学习｜知识库；
- 形态：轻薄磨砂玻璃，悬浮在页面安全区上方；
- 选中态：文字加深、位置标记或轻微内凹，不使用彩色填充胶囊套胶囊；
- 导航背景不应遮挡页面核心内容；
- 键盘弹出时根据场景收起或避让，不与输入框争夺底部空间。

### 10.2 对话圆形入口

- 与导航胶囊并列但视觉独立；
- 可以略高、略厚，但不能成为压过三个目的地的巨大悬浮按钮；
- 内部使用抽象、黑白、中性的对话标识；
- 打开 Agent 后转为收起状态，并维持与抽屉的因果关系；
- 不拟人化，不使用机器人或通用 AI 星芒符号。

### 10.3 Agent 抽屉

- 默认覆盖约 75%，后方页面轻微暗化但仍可辨认；
- 顶部展示名称、新建对话和历史记录入口；
- 当前页面以可移除的弱上下文标签呈现；
- 首次打开提供一句输入提示和 2–3 条与当前页面相关的建议问题；
- 输入框固定在底部安全区；
- 全屏后表面更接近实体，适合长时间阅读；
- 没有用户资料时明确说明回答来自通用知识。

### 10.4 节点抽屉

- 与 Agent 抽屉共享空间材质和吸附逻辑；
- 内容结构：知识点概要、主题路径、邻近节点、深入学习入口、相关资料跳转；
- 后方地图保留少量可见区域，维持节点与抽屉的空间连续性；
- 切换邻近节点时，抽屉内容和地图焦点协同移动；
- 不在抽屉中阅读完整课件、文章正文或笔记全文。

### 10.5 主按钮

- 使用炭黑或近白实体表面；
- 中等圆角，不使用玻璃；
- 每个页面原则上只有一个最高优先级主按钮；
- 禁用态通过对比度、文字和交互共同表达，不能只降低透明度到不可读；
- 按下反馈短促、轻微下沉，不使用夸张缩放。

### 10.6 标签与上下文标签

- 使用小到中等圆角；
- 背景接近中性色，只用少量类别色标记来源；
- 可删除标签必须有明确删除目标与足够触控面积；
- `梯度下降 ×` 与 `全知识库` 等标签需要清晰区分“当前优先上下文”和“Agent 的实际能力范围”。

### 10.7 列表

- 主要依靠行高、对齐和细分隔线组织；
- 默认不使用独立卡片和阴影；
- 缩略图、文件类型、来源、更新时间和状态按稳定列对齐；
- 滑动操作应克制，并提供可发现的替代入口；
- 选中和多选状态不能只依赖背景色。

## 11. 核心页面的视觉节奏

### 11.1 今日

关键词：**安静、明确、单一焦点。**

- 页面拥有最大的留白；
- 首要行动和当前状态占据主要视觉层级；
- 其他可做与最近变化退居次级；
- S10 完成后不立即填入新任务，保留明确结束感；
- 成果反馈可以短暂出现局部地图缩略图，但不演变成数据仪表盘。

### 11.2 学习与知识地图

关键词：**开放、连续、有关系。**

- 地图是全产品颜色最丰富、空间自由度最高的区域；
- 节点更接近具有面积和层次的知识斑块，而非发光小球；
- 颜色表达知识类别，位置表达关系，大小表达结构重要性或焦点；
- 最近变化可使用短期光晕，学习状态仅作为可选图层；
- 当前视口允许节点越过边缘，不把完整网络压缩进单一画面。

### 11.3 深入学习

关键词：**集中、稳定、有阶段。**

- 正文区域收窄，减少干扰；
- 阶段感通过结构和垂直节奏表达，不使用游戏化进度环；
- 引用与来源清晰但不抢夺正文层级；
- 交互控制保持固定和可预期；
- 完成时信息归拢，而非向外爆发。

### 11.4 知识库

关键词：**编辑式、高密度、不拥挤。**

- 以列表和稳定列对齐为主；
- 搜索、筛选和空间切换位于轻量控制层；
- 文件、知识空间和资料正文保持清晰层级；
- 不采用 SaaS 式卡片矩阵；
- 高信息密度来自排版效率，而不是压缩字体和点击区域。

### 11.5 自由 Agent

关键词：**中性、连续、可随时唤起。**

- 抽屉继承当前页面，但不抢走其视觉身份；
- 消息排版以阅读为主，不做彩色气泡堆叠；
- 引用、上下文和转换到深入学习的入口清晰可见；
- 建议问题轻量呈现，不能像首页功能卡片；
- 全屏状态适合长对话，75% 状态保留当前页面的弱上下文。

## 12. 状态、反馈与可访问性

### 12.1 状态反馈

- 加载：优先使用结构占位和局部进度，不让整页持续旋转；
- 成功：简洁确认并自然归位，不使用庆祝动画；
- 错误：明确说明发生了什么、哪些内容仍被保留、用户可以做什么；
- 空白：解释当前状态，并提供一个明确行动；
- AI 处理中：显示阶段和来源边界，不伪装成已经完成；
- 引用与生成内容：在视觉上可区分、可追溯。

### 12.2 对比度与可读性

- 正文和关键控件满足 WCAG AA 对比度目标；
- 玻璃下方背景变化时，文本层应有稳定保护；
- 小字号不使用低饱和彩色文字；
- 交互目标满足移动端可触控尺寸；
- 焦点态、选中态、错误态和禁用态不得只依赖颜色。

### 12.3 动态与性能

- 手势响应与滚动流畅优先于实时模糊和复杂阴影；
- 低性能设备可以降低模糊、阴影层数和地图视觉细节；
- 降级后仍需保持层级、可读性和吸附逻辑；
- 支持系统减少动态设置。

---

## 13. 明确避免的视觉方向

- 卡片层层嵌套的 SaaS 仪表盘；
- Notion 式纯文档工具感；
- 蓝紫渐变、霓虹、玻璃卡片铺满页面的通用 AI 视觉；
- 发光节点、复杂粒子和科幻网络；
- 连续打卡、奖章、进度环与强游戏化反馈；
- 宋体或其他锋利、高装饰性的标题字体；
- 所有元素同时居中、对称和规整排列；
- 过度圆润、软糖回弹和卡通图标；
- 大面积纹理、装饰线、重阴影和无意义材质；
- 为展示动效而持续运动，或让动画阻碍阅读和操作。

## 14. 设计验收问题

每个页面和组件进入高保真或开发验收时，至少检查：

1. 如果移除颜色、阴影和动效，布局层级是否仍然成立？
2. 玻璃是否只用于控制与浮层，而没有扩散成内容卡片？
3. 页面是否只有一个清晰的最高优先级行动？
4. 颜色是否正在传递真实语义，而不是装饰？
5. 圆角是否符合组件等级，而不是所有元素统一圆润？
6. 动效是否解释了来源、去向、重量或关系？
7. 阻力是否保持跟手，吸附点是否足够少且可预期？
8. 抽屉关闭后是否恢复原页面状态和视角？
9. 字体、对比度、触控区域和减少动态模式是否可用？
10. 页面是否仍然符合“安静、克制、聪明、具有空间感”的产品气质？

## 15. 当前决策状态与下一步

### 15.1 已确认

- 产品采用编辑式极简主义；
- 理性网格作为骨架，局部使用不对称张力；
- 字体采用温和、清晰的现代黑体方向；
- 黑白为主，低饱和颜色小面积标注；
- 内容保持平面，导航、控制与抽屉使用局部磨砂玻璃；
- 组件柔和但不圆润泛滥；
- 动效核心是阻力、惯性与自动吸附；
- 地图与抽屉承担最明显的空间运动，普通内容保持克制。

### 15.2 需要通过高保真验证

- 中性色是否偏暖，以及暖度的最终程度；
- 知识类别色的数量、映射与辨识度；
- 地图节点最终采用斑块、标签或混合形态；
- 玻璃透明度、模糊强度与低性能降级效果；
- 导航胶囊与对话入口的尺寸比例；
- 75% 抽屉的实际高度、全屏转化和键盘联动；
- 地图惯性、边界阻力和弱吸附范围；
- 页面级排版尺寸在不同设备上的缩放规则；
- 是否需要深色模式，以及深色模式是否保留同一材质逻辑。

### 15.3 建议下一步

1. 基于本规范制作“今日、知识地图、知识库、Agent 抽屉”四张视觉基准页；
2. 先验证黑白比例、字体层级、玻璃材质和页面间节奏；
3. 再制作地图节点、抽屉和导航的交互动效原型；
4. 通过真机测试调整阻力、吸附、模糊与字体尺寸；
5. 最后沉淀为组件级 Design Token 与开发实现规范。
