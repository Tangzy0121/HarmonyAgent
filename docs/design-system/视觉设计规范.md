# 视觉设计规范

**版本：** V1.2

**状态：** 当前有效基线

**更新日期：** 2026-07-31

**基准实现：** `admin/` 不透明视觉重构，390 × 844px 标准视口

## 1. 文档目的

本文定义 `loci` 当前真实视觉口径，供 Web 高保真原型、ArkUI、Android 与 iOS 实现共同使用。机器可读 Token 与组件事实源为仓库根目录 `DESIGN.md`；本文解释设计意图、页面应用和验收边界。

本版本替代此前的“雾银知识场”和 Liquid Glass 方案。旧玻璃实验集中保留在 `admin/archive/glass/`，仅供追溯，不进入生产构建，也不得作为新端迁移基准。

## 2. 核心视觉命题

> **矿物索引：用浅矿物灰、深色编辑排版、稳定实体表面和稀缺珊瑚桃色，构成安静而精密的个人知识空间。**

产品的生命感来自用户操作后的因果反馈、知识关系和状态变化，而不是环境光、辉光、折射、背景纹理或持续动画。

核心特征：

- 浅矿物灰连续画布；
- 深梅黑主文字与三档清晰文本层级；
- 珊瑚桃色只标记品牌、Agent 和即时行动；
- 冷紫只表示待复习，绿色只表示成功；
- 开放式列表和阅读小节；
- 只有明确对象与覆盖关系才使用实体容器；
- 底部控制与抽屉可使用一层克制阴影；
- 不使用渐变、背景模糊、折射或环境光。

## 3. 跨端设计原则

### 3.1 默认不透明

所有正式组件以不透明实体为默认。设计不得要求平台提供 `backdrop-filter`、实时高斯模糊、背景采样、位移折射或自定义 Shader 才能成立。

### 3.2 排版先于容器

内容层级按以下顺序建立：

1. 字号和字重；
2. 留白和对齐；
3. 单像素分隔线；
4. 低层实体底色；
5. 只有悬浮或覆盖关系才使用阴影。

如果移除卡片背景后信息仍能清楚理解，则该卡片不应存在。

### 3.3 桃色稀缺

一个视口原则上只有一个珊瑚桃色实心锚点，例如 Agent 入口、添加或发送。普通主操作使用深梅黑；筛选、返回、定位和历史不得使用桃色实心面。

### 3.4 领域状态可读

当前学习、待复习、已掌握、错误等状态必须同时提供文字、图标或形态。颜色是辅助编码，不是唯一信息源。

## 4. 色彩

准确值见 `DESIGN.md`，实现以 OKLCH Token 为准。

| 语义 | 用途 |
| --- | --- |
| `canvas` | 一级页面、地图与深层流程画布 |
| `canvas-deep` | 设备外背景或低层分区 |
| `surface` | 普通稳定表面 |
| `surface-raised` | 焦点任务、搜索、命令面板、抽屉 |
| `surface-muted` | 图标底、标签、引用和次级聚合 |
| `ink` | 标题、正文、关键图标 |
| `ink-secondary` | 说明和辅助正文 |
| `ink-tertiary` | 元数据、时间、位置和占位 |
| `line` / `line-strong` | 分隔与焦点边界 |
| `accent` | Agent、添加、发送、当前行动 |
| `review` | 待复习与回顾 |
| `success` | 已掌握、完成与确认 |
| `nav` | 底部导航和通用主按钮 |

禁止：

- 页面级渐变；
- 彩色辉光和环境光斑；
- 霓虹蓝紫 AI 色带；
- 大面积纯黑背景；
- 依赖半透明叠层获得层级；
- 多块互相竞争的桃色实心区域。

## 5. 排版

### 5.1 字体

中文正文优先使用 Noto Sans SC、PingFang SC 或 HarmonyOS Sans SC；标签与元数据可使用 DM Mono 或平台等宽字体。平台可使用对应系统字体，但必须保持相近字面宽度和字重。

### 5.2 层级

| 层级 | Web 基准 | 用途 |
| --- | --- | --- |
| Display | 52 / 600 / 0.98 | “今日”等极短一级标题 |
| Headline | 38 / 600 / 1.04 | 一级页面标题 |
| Title | 30 / 600 / 1.12 | 焦点任务与阶段标题 |
| Body | 15 / 400 / 1.75 | 阅读正文和说明 |
| Label | 10 / 500 / 1.4 | 状态、时间、位置和元数据 |

各端使用固定语义字号，不依赖视口插值。一级标题最多两行；标签不得承担关键说明；700 字重只用于极短且确有必要的标题。

## 6. 布局与表面

### 6.1 画布

- 主内容宽度支持 320–480px；
- Web 标准验收视口为 390 × 844px；
- 页面水平边距为 22px，窄屏降为 18px；
- 安全区由各端系统 API 提供；
- 桌面 Web 只居中展示移动画布。

### 6.2 开放内容

正文、概念、资料、行动、证据、消息与历史记录默认不设置行背景，通过分隔线和 12–24px 的节奏组织。

### 6.3 稳定表面

只在以下场景使用 `surface-raised`：

- 今日焦点学习任务；
- 搜索；
- 地图命令面板；
- 地图详情或变化面板；
- Agent 抽屉和底部输入；
- 需要持续边界的验证选项。

表面使用 1px 边界，不使用内高光或背景采样。内部不得继续嵌套同权重卡片。

### 6.4 阴影

只有底部导航、Agent 入口、Agent 抽屉和地图覆盖面板允许一层中性宽阴影。内容面、列表行、搜索、验证选项和阅读分区不得使用阴影。

## 7. 核心组件

### 7.1 底部导航

- 高 68px，圆角 22px，深梅黑实体；
- 3 个目的地均分；
- 当前项使用浅色实体与深色文字；
- 位于安全区上方 16px；
- Agent 为独立 68px 珊瑚桃色入口，不是第四个 Tab。

### 7.2 今日焦点

- 浅色实体面、24px 圆角、1px 边界；
- 首部状态与标题间保留较大留白；
- 标签使用低层实体底色；
- 来源区用分隔线收束；
- “继续学习”等主要 CTA 使用深梅黑实体。

### 7.3 搜索与筛选

- 搜索高 52px、圆角 14px、实体表面；
- 筛选高 36px、圆角 10px；
- 激活筛选使用深梅黑实体；
- 不使用毛玻璃、折射或浮动光影。

### 7.4 列表

- 普通行高不小于 74px；
- 整行背景透明；
- 行与行之间使用单像素分隔线；
- 图标可使用 36–38px 的 `surface-muted` 底；
- 状态标签采用低对比实体底色；
- 禁止一行一卡和多层阴影。

### 7.5 学习地图

- 使用纯色 `canvas`；
- 关系线为中性细线，选中关系使用语义色；
- 节点为浅色实体面与 1px 边界；
- 聚焦使用边界增强和最多 1.04 缩放；
- 禁止节点光晕、环境纹理、辉光背景与持续脉冲；
- 地图详情以底部实体面板覆盖，不模糊下层内容。

### 7.6 Agent

- 默认高度约 75%，支持关闭和全屏；
- 默认态顶部圆角 26px，全屏态为直角页面层；
- 抽屉和输入区均为实体浅色表面；
- 对话、引用、提示词和历史记录使用开放列表；
- 不使用聊天气泡、厚玻璃或半透明遮罩内容；
- 遮罩只承担覆盖语义，使用固定深色透明度，不做背景模糊。

### 7.7 深层学习流程

文件理解、解释、验证和完成页采用连续阅读：

- 顶部导航为实体固定层；
- 正文与证据使用开放小节和细线；
- 图表使用实体浅色面与边界；
- 反馈可使用低彩语义底色和左侧窄标记；
- 底部主操作为实体固定层；
- 不堆叠卡片，不改变为独立暗色主题。

## 8. 动效与手势

| 场景 | 时长 | 说明 |
| --- | --- | --- |
| 按压、选中、筛选 | 160–220ms | 颜色、边界、最多 0.95 缩放 |
| 页面局部状态 | 180–260ms | 保持来源与去向可理解 |
| 地图聚焦、抽屉吸附 | 260–320ms | 可使用阻力与吸附 |

禁止持续漂浮、背景视差、光照呼吸、装饰粒子和无意义弹跳。系统开启减少动态时，取消非必要过渡；拖拽仍需保留直接操控反馈。

## 9. 无障碍

- 关键触控目标至少 44px；
- 键盘聚焦使用 2px 高对比轮廓；
- 文本对比在固定实体背景上验证；
- 状态必须有非颜色表达；
- 内容放大后允许增长和滚动；
- 抽屉、面板、导航和地图节点提供可访问名称与状态；
- 安全区、键盘和系统返回由原生平台处理。

## 10. 跨端映射

三端共享：

- 语义颜色、字号、间距、圆角和动效 Token；
- 组件职责和状态；
- 模拟数据与验收截图；
- 页面流和系统返回语义。

三端各自实现：

- 布局与安全区；
- 手势、地图和抽屉；
- 字体映射；
- 导航栈与系统能力；
- 无障碍语义。

不得共享或复刻：

- CSS 级联；
- SVG / Canvas 折射滤镜；
- 背景位图与环境光；
- 实时背景模糊；
- 依赖 Web 祖先选择器的覆盖关系。

## 11. 验收清单

1. 关闭透明、背景图和模糊后，层级是否仍完整？
2. 是否先用排版、留白和分隔线，而不是新增卡片？
3. 单个视口是否只有一个桃色实心锚点？
4. 普通列表是否保持开放？
5. 深层页面是否保持连续阅读？
6. 地图节点是否无光晕、无环境纹理？
7. 状态是否同时有文字或图标？
8. 所有关键触控是否至少 44px？
9. 减少动态时是否仍可理解状态变化？
10. 组件能否直接映射为 ArkUI 和 React Native 的实体布局？

## 12. 当前实现边界

`admin/src/index.css` 是当前生产视觉事实源；`admin/archive/glass/` 是归档。正式构建中不得出现以下字符串或能力：

- `backdrop-filter`
- `feDisplacementMap`
- `loci-glass`
- 页面环境光节点
- 背景辉光或模糊光斑

如未来重新评估特殊材质，必须作为独立实验提出性能预算、降级方案与跨端价值证明，不能直接回到产品基线。
