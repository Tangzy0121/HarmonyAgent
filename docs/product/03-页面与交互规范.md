# 页面与交互规范

> 状态：已确认
>
> 更新日期：2026-08-24

## 1. 页面清单

| 页面或层 | 页面职责 | 最高优先级动作 |
| --- | --- | --- |
| 今日 | 决定现在最值得做什么 | 执行主推荐 |
| 学习库 | 找到并管理学习项目 | 继续一个项目 |
| 新建项目 | 选择来源和学习设置 | 生成学习方案 |
| 方案确认 | 审阅并确认学习路径 | 生成第一章 |
| 项目概览 | 查看方案、章节、来源和设置 | 继续学习或恢复任务 |
| 学习书工作区 | 连续阅读、验证和探索 | 完成当前章节动作 |
| 概念图模式 | 理解概念关系和掌握状态 | 查看概念或关系依据 |
| 复习任务 | 巩固有限概念 | 提交当前回答 |
| 全书总结 | 回顾成果和后续方向 | 返回今日或开始新项目 |
| Chat | 基于明确范围提问和协助 | 发送问题 |
| 来源查看器 | 核查引用和上下文 | 返回原位置 |

目录、Chat、来源查看器和复习任务不是新的一级导航。

## 2. 应用外壳

### 2.1 一级导航

- 一级内容入口只有“今日”和“学习库”。
- 当前移动端原型不设置常驻底部导航、Profile 入口或悬浮 Agent 入口。
- 一级页面左上角使用两条不等长细线打开全屏文字导航；右上角只保留 loci 标志。
- Chat 只在章节、概念和选中文本等明确上下文中出现，不成为一级导航。
- 进入沉浸页面后使用顶部返回；返回时恢复原入口和原位置。
- 当前原型只设计移动端。宽屏仅居中展示移动画布，不扩展桌面导航和桌面页面。

### 2.2 视觉基线

- 屏内背景使用纯黑，屏幕外保持银灰色。
- 层级依靠字号、字重、灰度、语义断行、细线和留白建立。
- 不使用环境光、渐变、高光、投影、内阴影、模糊或毛玻璃。
- 普通内容直接落在画布上；只有独立学习目标和必要控件使用纯色色块。
- 现行颜色、排版、间距和组件细则以 `prototype/DESIGN.md` 为准。

### 2.3 全局通知

`ProjectNotice` 使用紧凑横幅、角标或系统通知。横幅一次只突出一个最高优先级状态，包含项目名、简短说明和一个处理入口。

普通成功不必占据横幅；需要用户行动的失败、方案待确认和重要后台完成可以提示。通知不得替代今日推荐。

## 3. 今日

### 3.1 页面结构

1. 页面标题和本周日历；
2. 可选项目通知；
3. 横向学习目标卡片；
4. 卡片分页提示和日期切换。

今日保持单屏，不支持页面纵向滚动。学习目标卡片通过原生横向滑动和 `scroll-snap` 切换，下一张保留少量露出。卡片、分页提示和日期切换整体沉在屏幕底部，中间留白随屏幕高度调整。

每张卡片只保留短标签、核心标题、一句提示、预计时间和一个主动作。标签、标题、说明和操作分别使用统一的水平轨道，同级文字在不同卡片中保持同一高度。推荐理由引用最近证据、进度或复习时间，不使用“为你精选”等空泛文案。

不同学习目标可以使用灰蓝、雾灰或暖石色，但明度和饱和度保持接近；颜色由目标固定，滑动时不换色。

### 3.2 推荐操作

- 开始；
- 换一个；
- 稍后；
- 今天不做此项。

拒绝理由可以询问但必须可跳过。一次拒绝不能自动成为永久偏好。

### 3.3 空状态

没有项目时，主推荐是“创建第一个学习项目”。没有到期任务且全部项目完成时，推荐回顾旧项目或创建新项目。不得展示伪造统计和占位任务。

### 3.4 禁止内容

今日不放项目列表、文件队列、概念图预览、打卡、总时长、掌握度大盘、最近浏览和消息中心。

## 4. 学习库

### 4.1 页面结构

1. 标题、搜索和“新建学习项目”；
2. “进行中｜已完成｜已归档”筛选；
3. 按最近学习时间排列的紧凑项目列表。

首版不增加文件夹、标签系统和复杂排序。

### 4.2 项目卡片

卡片显示：

- 当前状态和最近时间；
- 精简项目标题；
- 当前章节进度；
- 来源格式；
- 一个与卡片点击一致的主动作。

卡片不展示学习目标、完整文件名、文件大小、上传日期、概念总数、多个分数和全部生成步骤。标题最多占两行；同级元数据保持对齐。右上角新建按钮中的加号必须在圆形内几何居中。

### 4.3 管理动作

更多菜单可提供重命名、暂停、归档。永久删除位于项目设置深处，必须说明会影响学习书、对话、笔记和学习证据。

## 5. 新建项目与方案确认

### 5.1 选择来源

- 支持 PDF、Markdown 和 DOCX；
- 文件选择后只显示识别所需的简短名称、格式和移除入口；
- 失败时保留已完成上传并允许重试；
- 首版一次创建只选择一份来源。

新建项目统一为“来源、设置、确认”三步。顶部只显示当前步骤和简短进度，不重复说明整条流程。

### 5.2 学习设置

只询问：

- 学习目标；
- 当前水平；
- 学习深度。

每个字段说明其用途。目标允许自由输入和少量示例，不把选项限制成唯一答案。

当前水平和学习深度各使用一行三列选项。标签与说明使用短文案，避免六个选项纵向堆叠。

### 5.3 方案确认

显示学习目标、学习水平、学习深度、总预计时间，以及章节标题和每章预计时间。详细目标和覆盖概念留到项目详情。用户可以修改标题、顺序或删除章节。

主动作是“确认并生成第一章”。确认前不批量生成全部正文；确认后第一章优先，其余章节后台生成。

## 6. 项目概览

项目概览是管理入口，不是每次阅读前的必经页。它包含：

- 学习目标和深度；
- 章节状态；
- 已读、已验证和待复习信息；
- 来源资料与依据；
- 方案调整、项目设置和归档。

有可读章节时，项目卡片默认直接回到阅读器。概览从阅读器更多菜单进入。

## 7. 学习书工作区

### 7.1 信息分层

- 内容模式：正文、概念图；
- 导航层：章节目录；
- 助手层：Chat；
- 证据层：来源查看器；
- 任务层：复习。

这些层共享同一个学习书上下文，不通过互不相干的路由复制状态。

### 7.2 手机端

- 正文全宽；
- 目录使用抽屉或顶部层；
- Chat 和长来源使用全屏层；
- 关闭覆盖层后恢复原块和滚动位置；
- 阅读期间不常驻底部一级导航。

### 7.3 章节头部

显示章节标题、学习目标、预计时间、来源范围和阅读/验证状态。不把掌握百分比作为标题区主信息。

### 7.4 正文块

正文按教学顺序组织。引用就近出现，清楚区分“资料依据”和“Agent 补充”。用户选中文字时提供“解释、对比、提问”，并将选中范围带入 Chat。

### 7.5 测验和费曼

小测就地提交和反馈，反馈包含正确性、关键解释、依据和重试。费曼讲述通常位于章末，反馈指出已覆盖、遗漏、可能冲突及应回看的正文位置。

不跳转到独立讲解、验证或普通章节完成页。

### 7.6 章末总结

显示已形成的证据、待复习概念和三个出口：继续下一章、复习薄弱概念、询问 Agent。整本书完成时才显示项目级总结。

## 8. 概念图模式

### 8.1 默认范围

默认展示当前章节，并突出从正文进入时的概念。允许切换“当前章节｜整本学习书”。不默认展示跨书全局图。

### 8.2 图语义

节点表示概念；关系线必须显示明确类型，如依赖、组成、导致、对比或应用。学习状态是节点上的独立投影，不改变知识结构。

### 8.3 节点详情

显示一句话定义、直接关系、来源、学习证据、“回到正文”和“询问 Agent”。回到正文必须定位到相关块。

### 8.4 关系详情与纠错

显示关系类型、说明、来源和置信状态。用户可修改受控关系类型、标记不成立并补充说明。系统保留原始生成结果和用户纠正，不在再生成时静默覆盖。

首版不做自由拖拽、任意画线和复杂布局编辑器。

### 8.5 手机端

以当前概念为中心只显示一层关系，并提供等价关系列表。点击相邻概念后重新聚焦，避免把桌面毛线图缩小到手机屏幕。

## 9. Chat

### 9.1 容器

手机端使用全屏层或适合短片段的底部层。入口只在有明确项目、章节、概念或选中文本上下文时出现；会话可以持续存在，但 Chat 不永久占用屏幕。

### 9.2 顶部

固定显示当前作用域、项目或章节名称，以及切换范围入口。作用域变化必须由用户看见并确认。

### 9.3 消息与引用

基于资料的关键判断附带可点击引用；外部常识标记为“补充说明”；证据不足时明确说明。回答底部可以提供继续追问、查看来源和建议动作。

### 9.4 动作确认

保存笔记、创建复习题和调整学习重点等写操作使用确认卡片。Chat 不直接修改正文、方案、概念关系和掌握状态。

Chat 中收到文件时，引导用户进入统一新建项目流程，不启动第二套隐蔽导入流程。

## 10. 来源查看器

- 从引用进入时准确定位并高亮；
- 显示资料名称、页码或结构位置；
- 允许查看必要前后文；
- 清楚标记无法精确定位的页级引用；
- 返回后恢复原页面、焦点和滚动位置；
- 首版支持阅读、搜索、目录和缩放，不承担复杂编辑。

## 11. 复习任务与全书总结

复习一次覆盖 3—5 个概念，显示任务进度和随时退出。反馈必须回到来源和相关正文。

全书总结显示完成的章节、仍待复习的概念、代表性学习证据和继续方向。它不是成绩单，不使用奖章、积分和夸张庆祝。

## 12. 通用状态和无障碍

每个页面至少定义：加载、空、部分可用、失败、重试和离线/网络中断状态。长任务允许离开。

触控目标至少 44px；状态不只依赖颜色；支持系统减少动态；地图提供列表替代；键盘出现时不遮挡输入与提交；系统返回、页面返回和关闭覆盖层的语义保持一致。
