# 用户流程与状态模型

> 状态：已确认
>
> 更新日期：2026-08-24

## 1. 全局结构

用户始终处在同一个学习产品中，而不是在文件、地图、聊天和测验子产品之间跳转。

```mermaid
flowchart LR
    today[今日] --> project[学习项目]
    library[学习库] --> project
    project --> setup[创建与方案]
    project --> book[学习书工作区]
    book --> reading[章节正文]
    book --> graph[概念图]
    reading --> evidence[测验 / 费曼 / 复习]
    evidence --> today
    chat[上下文 Chat] -.按需进入.-> today
    chat -.按需进入.-> library
    chat -.带明确作用域.-> book
```

一级内容只有“今日”和“学习库”。移动端通过左上角菜单进入，不设置常驻底部导航。Chat 保留会话，但只从明确上下文按需进入，不是第三个内容 Tab，也没有全局悬浮入口。

## 2. 首次使用流程

### 2.1 主路径

1. 用户进入今日空状态。
2. 用户选择“创建第一个学习项目”。
3. 用户选择一份 PDF、Markdown 或 DOCX。
4. 系统创建项目草稿并开始上传、解析。
5. 用户填写学习目标、当前水平和学习深度。
6. 系统根据来源和设置生成学习方案。
7. 用户查看并确认章节、目标和预计时间；必要时调整标题、顺序或删除章节。
8. 系统优先生成第一章，其他章节进入后台队列。
9. 第一章可读后，用户进入学习书工作区。
10. 用户阅读、查看来源、向章节 Chat 提问并完成正式验证。
11. 系统保存事件和证据，更新概念状态投影。
12. 章末给出继续、复习薄弱概念或询问 Agent 的出口。
13. 今日根据最新状态生成下一项推荐。

### 2.2 创建流程的页面边界

创建只包含三个用户阶段：

- 选择来源；
- 学习设置；
- 确认方案。

上传、解析和方案生成是后台任务状态，不需要为每个技术阶段建立一张页面。用户离开后，学习库卡片和 `ProjectNotice` 负责恢复。

首版不在创建时询问预检题、模型供应商、生成参数、学习风格或复杂偏好。

### 2.3 中断与恢复

| 中断位置 | 必须保存 | 恢复入口 |
| --- | --- | --- |
| 上传中 | 项目草稿、文件名、已上传状态 | 学习库项目卡片 |
| 解析中 | 已完成阶段、错误和重试信息 | 项目状态页、通知横幅 |
| 学习设置 | 已填写目标、水平和深度 | 创建流程原步骤 |
| 方案确认 | 当前方案及用户修改 | 方案确认页 |
| 章节阅读 | 章节、块和滚动位置 | 今日推荐或项目卡片 |
| 测验/费曼草稿 | 未提交答案或讲述草稿 | 原验证块 |
| Chat | 会话、作用域和最后消息 | 原学习项目的 Chat 历史 |

中断不是失败。用户主动离开时不显示负面文案，也不自动丢弃草稿。

## 3. 日常学习流程

### 3.1 从今日进入

今日展示一条主推荐和最多两条备选。用户点击后直接进入任务发生的位置：

- 继续学习：回到最后章节和阅读位置；
- 复习：进入学习书内的短复习任务；
- 下一章：打开已生成章节；
- 恢复项目：进入项目概览或上次可用位置；
- 新项目：进入来源选择。

今日不先经过统计看板，也不要求用户重新选择项目。

### 3.2 从学习库进入

学习库点击行为取决于项目状态：

- 有可读章节：进入上次阅读位置；
- 等待第一章：进入方案与生成状态；
- 生成失败：进入可恢复的项目状态页；
- 已完成：进入全书总结；
- 已归档：进入只读项目概览。

### 3.3 章内循环

章节按“目标→讲解→示例→结论→来源→小测→费曼→总结”组织。小测可以在相关知识之后穿插；费曼讲述通常位于章末。

验证结果就地反馈，不跳转到独立验证页。章末总结只展示本章证据、薄弱概念和下一步，不建立普通章节完成庆祝页。

## 4. 复习流程

复习是学习书内部的一种短任务，可从今日、章末总结或概念详情进入。

```mermaid
flowchart LR
    entry[今日 / 章末 / 概念详情] --> queue[3—5 个概念]
    queue --> recall[主动回忆]
    recall --> apply[应用或对比题]
    apply --> explain[必要时简短讲述]
    explain --> result[结果与来源]
    result --> book[返回学习书]
```

复习队列必须有限、可结束、可稍后处理。用户完成一项后，系统先保存原始事件，再形成证据和新的状态投影。

## 5. Chat 流程

### 5.1 默认作用域

| 打开位置 | 默认作用域 |
| --- | --- |
| 今日 | 学习概况 |
| 学习库 | 所有学习项目的元数据与搜索范围 |
| 项目概览 | 当前学习项目 |
| 章节正文 | 当前章节 |
| 概念详情 | 当前概念 |
| 选中文字 | 选中文本及其来源位置 |

作用域始终显示在 Chat 顶部。用户切换章节时，系统不得静默改变现有会话范围，应提示继续旧会话或创建新会话。

### 5.2 写操作

Chat 可以提出保存笔记、生成复习题或调整后续学习重点，但必须先展示确认卡片。取消不产生副作用。普通 Chat 消息永远不能直接写入 `ConceptState`。

## 6. 来源查看流程

用户从引用、概念关系或 Chat 回答进入来源查看器。系统应：

1. 打开对应资料；
2. 定位到页、章节、段落或文本区间；
3. 高亮当前引用；
4. 允许切换前后文；
5. 关闭后恢复原章节和滚动位置。

当前移动端原型优先使用全屏层或适合短片段的底部层。宽屏只居中展示移动画布，不增加桌面侧栏或固定分栏。

## 7. 项目生命周期

### 7.1 用户状态

| 状态 | 含义 | 主动作 |
| --- | --- | --- |
| 草稿 | 来源或设置尚未完成 | 继续创建 |
| 准备中 | 正在上传、解析或生成方案 | 查看进度 |
| 待确认 | 学习方案可以审阅 | 确认方案 |
| 进行中 | 至少一章可读或可继续生成 | 继续学习 |
| 受阻 | 当前阶段失败，但已有数据保留 | 重试或修正 |
| 已完成 | 用户完成学习书的计划范围 | 查看总结 |
| 已归档 | 项目退出日常推荐和默认列表 | 查看或恢复 |

### 7.2 技术任务状态

上传、解析、方案生成和章节生成分别保存 `pending / running / ready / failed / paused / cancelled`。项目状态由这些事实投影得出，不用一个模糊枚举覆盖所有后台任务。

后续章节失败不能阻止用户阅读已有章节。失败重试必须幂等，不能重复创建章节或重复写入学习证据。

## 8. 概念状态

用户侧只显示：

- 未验证；
- 学习中；
- 已掌握；
- 待复习。

“未验证”不等于“不会”，“待复习”不等于“已经忘记”。状态详情必须列出支持判断的证据和时间。内部置信度可用于排序，但首版不显示虚假的精确百分比。

## 9. 异常与恢复原则

- 长任务允许离开，完成后通过项目通知或角标提示。
- 错误不得覆盖已有可用内容。
- 部分成功时先提供可用结果，并说明缺失部分。
- 重试从失败阶段继续，不重复已经完成的工作。
- 来源丢失时保留学习记录，但清楚标记无法定位的引用。
- 所有不可逆删除都需要二次确认；整理优先使用归档。
