## Part A · 产品构想

### 0. 一句话定位

**Obsidian + Agent：一个住在鸿蒙系统里、越用越懂你的自进化学习伙伴。**

用户把教材PPT、课件、笔记"投喂"给它，它在端侧建立个人知识库；它持续维护一个"学习者模型"（你学了什么、哪里卡壳、最近在专注什么），并在对的时刻主动出现——通过小艺推送、对话、卡片，引导你学习。

技术路线已定：**端A2A**。Agent 住在我们的鸿蒙 App 里，通过 AgentExtensionAbility 与小艺通信；用户日常交互发生在小艺（对话/语音/chips推荐/胶囊），App 是知识库管理与可视化的地方。**"知识不出端"是我们的核心卖点之一。**

### 1. 亮点一：自进化（核心差异点）

竞品都是"导入文档→问答"的死水RAG，我们的差异是**知识有生命周期，Agent 有成长**。

- 学习者模型持续记录：每个知识点的掌握度、你的学习习惯（活跃时段、偏好方式）、当前学习焦点（有衰减，会自动切换）；
- 掌握度的来源是可观测行为：问答正确率、复习时自评、页面停留时长——**规则更新，不是LLM瞎猜**；
- 典型场景：
  - 你在某一页停留过久 → Agent 默默提示，"点化"你没懂的地方；
  - 你在学机器学习，但学习者模型发现你线代部分掌握度已衰减 → 主动提示"这块可能需要先补一下行列式"，引导复习；
- 演示时的"哇塞点"：学习者模型可视化——掌握度热力图、知识网络随时间生长。

### 2. 亮点二：引导学习（这块交给你，下面是我的初步思路 + 开放问题）

投喂的材料不只是存起来，而是被**加工成可交互的学习件**：

- Agent 把材料结构化成**知识件**：概念卡、定理卡、例题卡（内容含 LaTeX 公式，App 内 KaTeX 渲染），外加一张**思维导图/知识网络**作为全局索引；
- 用户以"索引卡片"的方式交互：卡片流、翻面看答案、点节点跳转关联卡片——本质是把 Anki 的卡片盒 + Obsidian 的双链做成 Agent 自动生产的形态；
- 与小艺侧的衔接：复习会话走端A2A的"长时任务伴随"（对话胶囊逐题进行、状态胶囊显示"今日复习 3/8"），单张卡片结果可以用 AgentUIExtensionAbility 自定义卡片呈现。

**没想透、需要你设计的开放问题**（按重要度排序）：

1. **卡片的第一入口在哪？** 是用户在小艺里说"帮我预习第3章"直接出卡片流，还是引导进 App？（我倾向前者演示、后者沉淀，但交互闭环你定）
2. **卡片交互的"手感"**：翻面、掌握度自评（认识/模糊/忘了三档？）、滑走逻辑——怎么做得比 Anki 轻、比刷短视频有获得感？
3. **思维导图的角色**：只是展示，还是可操作的学习路径导航（点节点 → 出对应卡片组 → 掌握度变色）？
4. **LaTeX 材料的边界**：自动生成做到什么程度？（概念/定理/公式抽取是下限，自动出题是上限，中间哪档性价比最高？）
5. **防枯燥机制**：卡片学习很容易弃坑，要不要有节奏设计（每日剂量、连续打卡、难度爬坡）？

> 设计约束（别越界）：① 第一交付物是比赛演示，设计要服务于"3分钟看懂差异"；② 卡片数据必须能写回学习者模型（每次交互都是掌握度的数据源）；③ 别设计成另一个独立笔记软件，小艺侧的对话入口永远是主入口。

### 3. 亮点三：终生学习（叙事层）

- 端侧知识库长久维护，跨学期、跨学科沉淀：大一线代的笔记，大三学ML时还在发光；
- 知识之间的关联随时间生长（新摄入的内容自动链接旧笔记），这就是"第二大脑"；
- 隐私叙事：学习数据是最私密的数据之一，**知识不出端**（存储、检索、画像全在本地，只有生成环节调云端大模型）。

### 4. 演示动线草案（供你设计时参考，可改）

1. 用户刷到/收到一份《机器学习》PPT → 直接对小艺说"帮我整理这个，下周要预习" → 文件通过端A2A传给Agent，长时任务伴随展示摄入进度（状态胶囊：解析→切块→入库→生成卡片）；
2. 30秒后：小艺返回章节摘要 + 预习卡片组（卡片可交互），并提示"检测到与3个月前的线代笔记相关，已建立关联"；
3. 晚上（学习者模型判断该复习了）→ chips主动推送"今天学的梯度下降，有3张卡该复习了" → 点进复习会话（对话胶囊逐题，状态胶囊 3/8）；
4. 收尾镜头：App内掌握度热力图 + 知识网络生长动画。
