# 旧版界面恢复、冗余清理与文档口径记录

> 日期：2026-07-31
> 状态：代码恢复与基础清理已完成；跨端迁移文档仍需按最终视觉决定复核
> 范围：`admin/` 高保真原型、根目录产品与设计文档、跨端迁移相关文档

## 1. 背景与最终结论

本阶段先后讨论了 ArkUI 迁移、未来 Android / iOS 客户端方案、React 原型的组件维护问题，以及降低玻璃材质和环境光照复杂度的视觉方向。期间曾在现有原型上尝试白绿配色、实体表面、减少描边、手机轮廓和新的导航样式。

实际预览表明，这组修改已经偏离“维护并迁移现有版本”的目标，形成了一套新的视觉重做，且丢失了原版的空间层级和 App 质感。因此最终决定是：

1. 放弃本轮白绿、扁平化和全面去玻璃的实现；
2. 恢复改版前的灰紫环境与烟晶悬浮控制版本；
3. 保留原版正在使用的材质、页眉、底部导航、Agent 和页面结构；
4. 只清理旧版中确认未被运行时使用的实验页、组件、数据和样式；
5. ArkUI、Android 和 iOS 后续迁移以“复现已确认体验”为目标，不再以本轮被否决的白绿版本作为基准。

## 2. 最终保留的视觉与交互基线

- 一级页面继续共享浅灰紫环境和深色排版；
- 正文、资料和学习内容保持稳定、可读的实体内容层；
- 页眉用户区、底部导航、Agent 入口、短时筛选和覆盖层继续使用原版材质；
- 底部导航保留浮动烟晶表面和选中态；
- Agent 保留独立入口、抽屉层级和原有花形身份符号；
- Today、Learning Map、Library 和深层学习流程继续沿用原版组件结构；
- 不新增手机外框或 Web 展示壳作为正式产品组件；
- 不保留白底、绿色装饰、黑色实体按钮组成的新视觉主题。

本阶段的正确交付物是“恢复并维护旧版”，不是一套新的视觉方案。

`admin/src/` 下已被白绿重做影响的正式页面、公共壳层、导航、Agent 和材质实现均恢复到改版前版本。生产环境继续使用现有的：

- `AppShell`

- 全局页眉

- Agent 入口与抽屉
- Today、Learning Map、Library 及深层学习页面

白绿版本新增的 `SystemStatusBar` 等实现未进入最终版本。

| 文件 | 处理 | 原因 |

### 3.3 历史归档与未处理资源

跨端迁移的核心技术结论仍然有效：

- HarmonyOS 在现有 `entry/` 中使用 ArkUI / ArkTS 原生实现；
- Android 与 iOS 可后续采用 React Native；
- React Web 原型用于视觉和交互参考，不直接搬运 DOM 与全局 CSS；
- 三端优先共享数据契约、领域语义、Token、Fixtures 和测试向量；
- 地图、抽屉、系统返回、安全区、文件选择和通知由各平台按原生能力实现。

需要重写的是迁移方案中的视觉映射，不是整个跨端架构判断。

3. 当前可运行的 `admin/`：具体组件与交互事实；
4. 其他设计系统和迁移文档：待专项复核，冲突处不得覆盖前三项。

## 5. 被撤销、不得继续累积的方向

以下内容是探索过程，不属于最终交付：

- 白色页面为主、绿色只做装饰、黑色主按钮的整套新主题；
- 花形符号统一改白；
- 大范围移除原版页眉和底部导航材质；
- 新增手机轮廓、系统状态栏和 Web 预览设备壳；
- 用新的通用 `Surface` 体系替换现有页面；
- 全面去除环境光、模糊和折射玻璃；
- 为适配 ArkUI 而先在 Web 端重新设计全部页面；
- 把旧版组件清理扩大为页面级重写。

后续如需降低玻璃复杂度，应逐组件评估性能、层级作用和原生等价实现，不能再次直接切换整套视觉语言。

7. 最后决定 Android / iOS React Native 工程的启动时间，不让多端工程同时拖动未稳定的设计。
