# P1 核心学习闭环高保真页面计划

**日期：** 2026-07-22

**状态：** 进行中（P1-01 至 P1-07 已完成，连续流程验收待执行）

**设计基线：** 《2026-07-22-mobile-app-reconstruction-plan-v2.md》与 `docs/design-system/` 当前 V1.0 规范

**实现范围：** `admin/` 移动端高保真前端原型，继续使用本地模拟数据

## 1. 阶段结论

P0 已经完成今日、学习地图、知识库和默认 75% Agent 抽屉四个视觉基准状态。P1 不继续增加互不相连的静态首页，而是复用这些基准页，构建一条能够连续演示和实际操作的核心学习闭环：

> 知识库资料 → 文件理解结果 → 单知识点深入学习 → 验证与反馈 → 地图变化 → 今日安排

同时补齐 Agent 从 75% 抽屉吸附到全屏的关键状态，使全局对话组件形成完整的空间行为。

本阶段仍不接入后端，不制作真实上传、模型推理或持久化。重点是页面构图、内容阅读、状态过渡、共享元素、阻力与吸附，以及从一个页面返回另一个页面时的上下文连续性。

## 2. 为什么先做这一批

1. 这条链路直接验证产品最核心的差异：资料不是被保存，而是被理解、转化为学习并沉淀到知识结构。
2. 它可以复用 P0 的知识库、地图和今日页面，检验现有视觉系统能否支撑真正的任务流，而不只是四张独立展示图。
3. 深入学习、地图变化和今日闭环包含正文、选择、反馈、完成与跨页面转场，可以覆盖下一阶段最关键的组件状态。
4. 注册、上传、设置等事务页对首轮视觉冲击和核心价值证明较弱，放在主闭环稳定后实现更合适。

## 3. 页面与状态范围

### P1-01 文件理解结果（S06）

**入口：** 从知识库点击《机器学习》第三章资料。

**核心问题：** Agent 从这份资料中理解了什么，我下一步可以学什么？

**页面结构：**

- 紧凑返回栏、资料名称与来源信息；
- 黑白几何封面与文件元数据形成编辑式开场；
- 一段可扫读的理解摘要；
- 核心概念、前置知识与章节结构；
- 引用来源和原文定位入口；
- 唯一主操作“开始深入学习”；
- 次操作“向 Agent 提问”和“在地图中查看”。

**视觉重点：** 使用纯白长阅读画布和纯黑重点区，不把摘要、概念和来源分别包装成同质卡片。Liquid Glass 只用于顶部瞬时控制和必要浮层。

**动效重点：** 从知识库封面进入时使用封面共享元素转场；摘要和概念按阅读顺序渐进出现，不做整页同时淡入。

### P1-02 深入学习：解释阶段（S08-A）

**入口：** 文件理解结果或地图节点信息面板中的“开始深入学习”。

**核心问题：** 我当前只需要理解哪一个知识点？

**页面结构：**

- 返回、当前知识点和阶段文字；
- 单一学习目标；
- 解释正文、必要图示与可追溯引用；
- “我理解了，继续验证”主操作；
- “换一种解释”和“查看来源”次操作。

**视觉重点：** 页面像原生阅读与学习工具，不像课程落地页。正文保持稳定白色实体表面，使用字号、留白、黑色重点段落和单色图示形成节奏。

**动效重点：** 知识点标题从前一页面的选中对象连续迁移；引用展开后从原锚点返回，不重置阅读位置。

### P1-03 深入学习：回忆与验证（S08-B）

**入口：** 完成解释阶段。

**核心问题：** 我能否用自己的理解完成一次可解释验证？

**页面结构：**

- 保留同一知识点和阶段上下文；
- 一个回忆问题或单项判断任务；
- 可选答案或短文本输入；
- 提交后的正确、部分正确和需要重看三种反馈；
- 反馈依据、对应原文和继续操作。

**视觉重点：** 不使用考试系统式彩色题卡或游戏化进度环。选择依靠黑白实体、描边、图标和文字共同表达；绿色与橙色仅作为小面积状态辅助。

**动效重点：** 提交后答案区域原位重组为反馈，而不是跳转到全新页面；反馈动效必须可中断并支持减少动态模式。

### P1-04 学习完成与证据归拢（S08-C）

**入口：** 完成验证。

**核心问题：** 我完成了什么，这次学习将如何进入长期知识结构？

**页面结构：**

- 克制的完成确认；
- 本次目标、理解结果、验证证据和引用来源；
- 将写入知识节点的学习记录预览；
- 唯一主操作“查看地图变化”；
- 次操作“返回今日”。

**视觉重点：** 不使用奖章、烟花、积分或彩色庆祝。内容向中心归拢，完成感来自空间收束和信息变得稳定。

**动效重点：** 学习内容折叠为一条“学习证据”，随后以共享元素进入地图中的目标节点。

### P1-05 地图变化聚焦（S09）

**入口：** 学习完成页的“查看地图变化”。

**核心问题：** 刚才的学习改变了哪一个节点和哪些关系？

**页面结构：**

- 复用现有学习地图页面与手势；
- 镜头聚焦“监督学习”节点；
- 新增关系使用短期青色标记，已掌握状态使用绿色小标记并配合文字；
- 约 30% 节点信息面板展示新增学习证据和来源；
- 主操作“安排下一次”。

**视觉重点：** 仍以纯白画布和黑白节点为主体，状态色不夺取知识类别的视觉主语义。

**动效重点：** 学习证据落到节点后产生一次低频脉冲；镜头与节点信息面板协同吸附，关闭后恢复聚焦前视口。

### P1-06 今日成果与下一次安排（S10）

**入口：** 地图变化页的“安排下一次”或学习完成页的“返回今日”。

**核心问题：** 今天已经结束什么，我是否要安排下一步？

**页面结构：**

- 复用现有“今天”大型页标题；
- 黑色焦点舞台由“待完成任务”转化为“今日成果”；
- 明天、今天继续和暂不安排三种选择；
- 默认主操作“安排到明天”；
- 完成后显示明确结束状态，不立即补充新任务。

**视觉重点：** 保持沉浸式黑色焦点构图，但信息从行动导向转为成果归拢；不演变成数据仪表盘。

**动效重点：** 当前任务轨道艺术减速并收束为完成轨迹；日期选择吸附到稳定落点，确认后页面安静下来。

### P1-07 Agent 全屏态

**入口：** 从任意页面打开 75% Agent 抽屉后继续上拉，或聚焦输入框并唤起键盘。

**核心问题：** 长对话时如何扩大阅读空间，同时维持与原页面的关系？

**页面结构：**

- 历史与新建对话入口；
- 可移除的当前弱上下文；
- 消息、引用和建议问题；
- 固定输入区与键盘避让；
- 明确的下拉返回 75% 和关闭操作。

**视觉重点：** 75% 状态使用厚 Liquid Glass；向全屏过渡时逐步变为纯白实体阅读表面。紫色仅作为 Agent 身份的小面积提示。

**动效重点：** 抽屉跟手、带边界阻力并根据位置与速度吸附；全屏与 75% 之间的材质变化必须连续，不能突然换皮。

## 4. 页面关系与状态保留

```text
知识库
  → 文件理解结果
    → 深入学习：解释
      → 回忆与验证
        → 完成与证据归拢
          → 地图变化聚焦
            → 今日成果与下一次安排

任意状态
  → Agent 75% 抽屉
    → Agent 全屏
    → 返回原页面与原位置
```

必须保留以下上下文：

- 从知识库进入和返回时的空间、筛选与滚动位置；
- 深入学习中的知识点、阶段、输入和引用锚点；
- 地图进入前的视口、缩放与筛选；
- Agent 打开前的原页面状态、会话草稿和抽屉高度；
- 今日安排完成后的结束状态。

## 5. 公共组件任务

1. 任务页返回栏与安全区容器；
2. 编辑式资料封面与共享元素容器；
3. 长阅读正文、引用脚注和来源预览；
4. 阶段文字与非游戏化学习进度；
5. 单选、短答、提交与三类反馈状态；
6. 学习证据摘要；
7. 固定底部主操作区与键盘避让；
8. Agent 全屏标题栏、消息区、上下文标签与输入区；
9. 页面级共享元素、前进/返回和减少动态替代转场。

组件继续遵守以下基线：单色 SVG、最小 44px 触控区域、4/8px 间距系统、纯黑纯白主色、辅助色不单独传达状态。

## 6. 模拟数据

继续使用《机器学习》第三章，不新增第二套内容主题：

- 当前文件：《机器学习》第三章；
- 当前知识点：监督学习；
- 关联节点：无监督学习、损失函数、梯度下降；
- 当前学习目标：区分监督学习与无监督学习的训练信号；
- 验证任务：根据训练数据是否包含标签判断学习类型，并解释依据；
- 学习结果：完成一次解释和一次验证，形成一条可追溯学习证据；
- 下一次行动：明天复习梯度下降。

## 7. 实施顺序

| 顺序 | 任务 | 依赖 | 主要交付 |
|---|---|---|---|
| 1 | P1-01 文件理解结果 | 现有知识库 | 页面、共享封面转场、引用入口 |

| 4 | P1-04 完成与证据归拢 | P1-03 | 完成摘要、证据共享元素 |

## 8. 每项任务的完成标准

每个任务完成时必须同时满足：

1. 页面或状态可以从真实入口点击进入，不只通过开发开关展示；
2. 前进、返回、关闭和系统返回语义一致；
3. 只有一个明确的最高优先级主操作；
4. 页面不出现落地页式“大口号 + 功能介绍 + 卡片预览”结构；
5. 正文和列表使用实体表面，Liquid Glass 只存在于控制与 Agent 浮层；
6. 所有图标使用统一单色 SVG，不使用 Emoji 或 Unicode 字符代替；
7. 触控目标至少 44px，固定控件避让安全区与键盘；
8. 动效能够说明来源、去向或状态变化，支持中断和减少动态；
9. 状态不只依赖颜色表达；
10. 在 `390 × 844` 主视口和一个不超过 `375px` 的小屏视口完成截图检查；
11. TypeScript 与 Vite 生产构建通过；
12. 在 `docs/worklog/prototype-building/results/` 写入对应中文结果文档。

## 9. 批次验收场景

用户应能连续完成以下操作，过程中不出现断开的演示页：

1. 在知识库打开《机器学习》第三章；
2. 阅读理解摘要并选择“监督学习”；
3. 完成一段解释阅读；
4. 回答一次验证问题并看到有依据的反馈；
5. 查看本次学习证据；
6. 进入地图，看见节点与关系变化；
7. 回到今日，把下一次行动安排到明天；
8. 从任意关键页面打开 Agent，拖动到全屏，再关闭并恢复原状态。

批次验收重点不是功能数量，而是用户是否始终知道自己在哪里、为什么进入下一步、刚才的内容沉淀到了哪里。

## 11. 阶段结束条件

满足以下条件后 P1 才能结束：

1. P1-01 至 P1-07 页面与状态全部可操作；
2. 主闭环可以从知识库连续走到今日结束状态；
3. Agent 75% / 全屏 / 关闭三个吸附状态稳定；
4. 页面视觉延续当前 V2，且不退化为网页落地页或卡片堆叠；
5. 主视口和小屏截图通过人工视觉检查；
6. 构建、差异检查和结果留档全部完成；
7. 用户确认这一批视觉和交互方向后，再规划 S01—S05 事务流程或 ArkUI 迁移。
