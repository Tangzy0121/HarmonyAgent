# ADR-002：统一产品口径与单一学习项目闭环

> 状态：已接受
>
> 日期：2026-08-24
>
> 决策范围：产品信息架构、学习项目、阅读器、Chat、学习证据、跨端后端边界

## 背景

仓库同时保留三套产品口径：早期“今日｜学习｜知识库＋Agent”、PR #7 的 Book 原型，以及《HarmonyAgent 产品设想与开发路线》中“今日学习｜Chat｜学习书”的讨论稿。它们对一级导航、文件与学习书的关系、概念图位置、验证页面和后端职责给出不同答案，已经无法作为同一实现基线。

PR #7 已于 2026-08-24 合并进 `master`，合并提交为 `c734b30`。它是可继续开发的工程基线，不是产品结构的最终答案。

## 决定

1. 应用主结构为“今日＋学习库＋持续存在的 Chat”。概念图属于学习书内部。
2. 用户侧只感知连续的“学习项目”。`Document`、`Book`、`Chapter` 等仍是后端独立对象。
3. 手机阅读器以学习书正文为主，来源按需打开，不使用默认拥挤分栏。
4. 概念图首版用于查看、溯源和受控纠错，不做自由画布编辑。
5. 今日只负责学习推荐；项目处理状态由 `ProjectNotice` 表达，不能替代主推荐。
6. 学习库只列学习项目，原始资料是项目的来源元数据，不作为并列列表项。
7. 新建流程采用“选择来源→学习设置→确认方案”。解析与方案生成可以在后台运行；首章优先生成。
8. 学习书是单一全屏工作区。目录是导航层，正文和概念图是内容模式，Chat 与来源阅读器是覆盖层；测验和费曼验证嵌入章节。
9. 概念图默认展示当前章节，支持切换整本书；关系必须有类型、理由和来源，并支持受控纠错。
10. 掌握状态只能由正式、可追溯的学习证据驱动。阅读、浏览和普通 Chat 不改变掌握状态。
11. Chat 的作用域始终可见；会话按学习项目组织；回答可溯源；写操作必须经用户确认。
12. 今日突出一条主推荐，最多提供两条弱化备选。每条推荐必须说明原因、项目和预计时间。
13. 学习库按进行中、已完成、已归档组织。每个项目只突出当前状态和一个下一步动作。

以上产品结构的架构结果是：`server/` 作为 Web 原型和 HarmonyOS 客户端共用的唯一业务后端与事实来源；`admin/` 和 `entry/` 不各自维护另一套业务真相。

## 影响

- 旧的独立学习地图、文件理解页、验证页和完成页不再作为并行主流程继续扩展。
- `admin/` 继续承担可运行原型与合同验证；`entry/` 承担真实 HarmonyOS 体验；两者通过同一 `server/` 契约获取业务状态。
- 现有额外内容块、预检、学习数据看板等实验可以保留代码，但不得默认进入首版流程。
- 旧 PRD 和设计系统文件保留为历史参考，并在顶部标明被本 ADR 覆盖的范围。
- 新增产品与技术文档统一收录在 `docs/product/`。

## 不在本 ADR 中改变的内容

- `loci` 的视觉语言、烟晶材质边界和无障碍原则继续遵循 ADR-001、`DESIGN.md` 与《视觉设计规范》。
- PR #7 中每项功能的真实完成度仍以 `MVP_SCOPE.md` 和后续端到端验收结果为准。
- 账户、生产存储、部署、多端同步和外部生态仍属于后续阶段。
