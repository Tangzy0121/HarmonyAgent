## 1. 状态定义

仓库中的页面、接口或文档必须使用以下状态，避免把“设计过”误解为“已经完成”。

| 状态 | 含义 |
| --- | --- |
| `Prototype` | 已有页面、实验实现或本地数据链路，但尚未完成真实端到端验收 |
| `Integrated` | 前端、服务端或 HarmonyOS 已按临时接口接通 |
| `Verified` | 使用真实文件、真实模型和目标客户端完成端到端验证 |
| `Planned` | 已形成产品或技术设计，但尚未实现 |
| `Deferred` | 当前阶段明确不做 |

测试和构建通过只能提升工程可信度，不能自动把功能标记为 `Verified`。上游大模型在自动测试中主要使用 Mock。

## 2. 当前原型主流程

当前代码围绕下面一条候选流程进行验证：

1. 导入一份 PDF、Markdown 或 DOCX；
2. 服务端在本地解析并保存资料；
3. 用户填写学习目标和当前水平，生成学习书提案；
4. 用户调整并确认目录，按章生成学习内容；
5. 用户阅读章节，完成测验或费曼解释；
6. 系统记录进度、学习证据并计算复习建议；
7. 当前学习书展示轻量概念关系；
8. Agent 默认在当前学习书或章节范围内回答。

这条流程目前是“待真实验收的可运行原型”，不是已经交付的产品闭环。

## 3. 当前能力状态

| 能力 | 当前状态 | 已存在的实现 | 转为 `Verified` 前仍需完成 |
| --- | --- | --- | --- |
| PDF / Markdown / DOCX 导入 | `Prototype` | 本地上传、解析、列表、删除和文档记录 | 三种真实文件分别完成解析与错误态验收；明确统一定位模型 |
| 互动学习书 | `Prototype` | 提案、确认、章节生成、流式事件和本地文件保存 | 使用真实模型完成稳定生成；验证重试、恢复、一致性和成本边界 |
| 测验与费曼学习 | `Prototype` | 作答、反馈、解释评价及相关接口 | 冻结评价结构；用真实章节验证结果可追溯且可复现 |
| 阅读进度 | `Prototype` | 章节访问、书签、完成度等本地状态 | 验证跨重启恢复、重复事件和异常状态 |
| 复习与学习证据 | `Prototype` | 基础事件、证据、掌握度和到期复习规则 | 明确 `LearningEvent`、`LearningEvidence`、`ConceptState` 的正式模型和更新规则 |
| 轻量知识地图 | `Prototype` | 当前学习书中的概念投影 | 重新设计关系类型、方向、理由、原文证据、置信度和确认状态 |
| 限定范围 Agent | `Prototype` | 当前书/章节上下文、工具调用和来源数据结构 | 真实模型验证引用、越界拒绝、会话恢复和失败处理 |
| Web 管理端 | `Integrated` | 原型页面与实验性服务端链路；自动测试和构建通过 | 用真实资料和真实模型完成完整人工验收 |
| HarmonyOS 客户端 | `Prototype` | HTTP Repository、Agent Gateway 和基础页面骨架 | DevEco Studio 构建；连接设备可访问的服务端并跑通核心流程 |
| 账户、正式存储和部署 | `Planned` | 暂无生产级实现 | 账户权限、数据库、对象存储、迁移、备份、部署、监控和安全设计 |

## 4. 当前实现边界

### 资料导入

- 只处理 PDF、Markdown、DOCX；
- 单文件目标上限 20 MB；
- 当前以单文件生成单本学习书；
- 暂不处理 EPUB、网页抓取、图片 OCR、音频或视频。

### Book

- 当前 Book 是实验性单机实现，不是正式内容生产系统；
- 生成依赖配置的大模型服务，未配置时应返回明确错误；
- 自动测试中的模型调用不代表真实供应商稳定可用；
- 本地 JSON 和文件保存不等于数据库、对象存储或多用户持久化；
- 章节生成的任务状态、失败重试和恢复策略仍需真实环境验收。

### 学习证据

- 测验、费曼解释和复习等明确行为可以产生候选学习证据；
- 普通聊天不能直接修改掌握状态；
- 模型评价不能直接作为不可纠正的学习事实；
- 正式版本需要保存原始学习事件，并让所有掌握判断可追溯。

### Agent

Agent 当前可以在实验链路中：

- 读取当前资料、学习书或章节上下文；
- 执行解释、归纳、举例、问答等学习操作；
- 返回当前实现能够提供的来源信息。

Agent 当前不能被描述为：

- 默认检索用户全部资料；
- 在没有资料依据时生成真实引用；
- 因普通对话直接更新掌握度；
- 执行任意文件系统、账户、网络或代码操作；
- 已具备可靠的长期个性化记忆。

### 知识地图

当前地图只是学习书范围内的轻量投影。它尚未实现正式的证据化学习概念图，不应把布局距离、模型相似度或无来源连线表述成确定的知识关系。

后续 `ConceptRelation` 至少需要包含：

- 关系类型和方向；
- 自然语言理由；
- 原文证据；
- 生成方法；
- 置信度；
- `candidate / confirmed / rejected` 状态。

## 5. 临时 API 基线

下列接口只用于当前 Web、HarmonyOS 与服务端原型联调，不是冻结的生产 API。字段可以在 Draft 阶段调整，但修改时必须同步客户端、测试和本文档。

| 场景 | 临时接口 |
| --- | --- |
| 资料 | `POST/GET /api/documents`、`DELETE /api/documents/:id` |
| 学习书 | `POST/GET /api/books`、`GET/DELETE /api/books/:id` |
| 提案与章节 | `POST /api/books/:id/confirm`、`POST /api/books/:id/chapters/:cid/generate` |
| 测验与费曼 | `POST /api/books/:id/attempts`、`POST /api/books/:id/chapters/:cid/feynman` |
| 进度与复习 | `POST /api/books/:id/progress`、`GET /api/books/:id/completion`、`GET /api/books/:id/review/due` |
| 学习证据 | `GET /api/learner/profile`，写入由测验、费曼和复习流程触发 |
| Agent | `POST /api/agent/turns`、事件、回答与取消接口 |

当前默认身份是 `local-user` / `local-workspace`，数据保存在服务端本地目录。这只是开发期约定。

## 6. 原型验收清单

以下项目全部通过后，只能说明“原型闭环已验证”，不能直接说明系统达到生产标准。

- [ ] PDF、Markdown、DOCX 各完成一次“上传 → 解析 → 创建学习书”；
- [ ] 使用真实模型生成提案，用户可以修改并确认；
- [ ] 至少一章完成生成、重新打开、失败重试和跨重启恢复；
- [ ] 一次测验和一次费曼解释形成可查询、可追溯的学习记录；
- [ ] 章节访问、书签、完成度和到期复习能够持久化；
- [ ] 地图只展示真实学习书数据，不把示例数据伪装成用户数据；
- [ ] Agent 在书级和章节级各完成一次对话，返回可见来源且不会越界；
- [ ] Web 完成主流程人工验收；
- [ ] HarmonyOS 在 `HTTP` 模式连接真实后端并完成核心读取和交互；
- [ ] `server` 与 `admin` 测试、构建通过；HarmonyOS 工程通过 DevEco Studio 构建；
- [ ] 未配置模型、网络失败、解析失败和生成失败均有明确错误态。

## 7. 当前不做

- EPUB、网页、图片 OCR、音视频等额外输入；
- 多资料合并成书、跨库检索和正式向量 RAG；
- 独立题库和复杂自适应测验；
- 自动维护的正式知识图谱或图数据库；
- 账户注册、登录、多租户和权限分享；
- 对象存储、正式数据库、云同步和生产部署；
- 小艺、A2A、通知、语音等连接器的产品化扩展；
- 为展示而单独设置 Memory 一级页面。

相关实验代码可以保留用于兼容或研究，但不得成为当前原型主流程的必经步骤，也不应继续增加无后端依据的占位入口。
