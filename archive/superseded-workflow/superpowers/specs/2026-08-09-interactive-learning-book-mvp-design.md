# HarmonyAgent 互动学习书 MVP 设计规格

**状态：** 已完成产品讨论并获用户批准  
**日期：** 2026-08-09  
**适用范围：** HarmonyAgent 第一轮真实能力 MVP  
**参考项目：** HKUDS/DeepTutor Interactive Book（Apache-2.0）

## 1. 设计结论

HarmonyAgent 的第一轮 MVP 以“互动学习书”为核心产品对象。一份用户上传的文本型 PDF 经解析后，先生成可编辑的目录提案；用户确认目录后，系统渐进生成由结构化内容块组成的互动学习书。用户可以在任意章节追问 Agent、查看原文引用、完成快速验证，并将学习结果沉淀为可解释的学习证据。知识地图是学习书知识点、候选关系、用户修正和学习证据的可视化投影，不是独立 Agent。

产品继续保持“今日｜学习｜知识库 + 独立 Agent 入口”的一级结构。互动学习书从知识库进入，不增加新的底部 Tab。

## 2. 问题与目标

现有原型已经具备文档阅读、知识抽取、候选关系、Agent 抽屉、深入学习、地图和今日建议等局部能力，但上传后的主要产物仍被描述为“文件理解结果”，各能力缺少统一承载对象。团队此前按“解析、出题、问答”划分 Agent，尚未明确每项能力的结构化输出、写入权限和上下文边界。

本设计的目标是用互动学习书统一资料解析、内容组织、章节问答、快速验证、知识地图和后续行动，并通过严格的输入范围与能力边界验证完整闭环，而不是在第一轮复制 DeepTutor 的全部功能。

## 3. MVP 范围

### 3.1 输入范围

- 每次处理 1—5 份来源文档（PDF、Markdown、DOCX、EPUB 任意混合），多份合成一本书；各份不超过 45,000 字，合计不超过 90,000 字。
- PDF 必须包含可复制的文本，不提供扫描件 OCR。
- 文件上限为 30 页或 20 MB，任一条件超出即在选择后、上传前明确阻止。
- 不接受加密 PDF。
- 生成前只额外询问学习目标和当前基础。
- 学习目标首版为“理解概念、课程学习、考试复习”。
- 当前基础首版为“入门、了解、熟悉”。

### 3.2 输出范围

- 一份 PDF 生成一本互动学习书。
- 一本书包含 3—6 章，每章预计阅读 5—8 分钟。
- 每章围绕一个核心知识点，可关联 2—4 个辅助知识点。
- 每章至少包含一处可定位的原文引用和 1—2 道快速验证题。
- 全书最多包含 30 个 AI 生成内容块；用户笔记不计入该上限。
- 系统不承诺覆盖原文每一句内容，未覆盖内容仍可在原文阅读层查看。

### 3.3 明确排除

- 扫描件、OCR、PPT、网页、音视频和手写笔记；
- 自动生成动画、Manim 视频或交互式 HTML；
- 多个自主 Agent 之间的对话协作；
- 自动把所有聊天内容写入知识地图；
- 根据单次答题计算精确掌握度；
- 小艺、手表、桌面卡片和跨设备流转作为核心入口；
- 社交分享、排行榜、积分、奖章及其他游戏化系统。

## 4. 产品结构

```mermaid
flowchart TB
    source["文本型 PDF"]
    parse["解析与页码定位"]
    proposal["学习书提案\n书名、概述、3—6 章目录"]
    confirm["用户确认\n改名、排序、合并、删除"]
    compile["渐进生成章节"]
    book["互动学习书"]
    chat["章节追问 Agent"]
    verify["快速验证与深入学习"]
    evidence["学习证据"]
    graph["知识地图"]
    today["今日下一步"]

    source --> parse --> proposal --> confirm --> compile --> book
    book --> chat
    book --> verify --> evidence
    book --> graph
    evidence --> graph
    evidence --> today
```

互动学习书负责组织学习内容，知识地图负责展示知识结构，Agent 负责生成、解释和问答，学习证据负责记录用户实际完成的学习行为。四者共享同一数据底座，但不相互冒充。

## 5. 用户流程

### 5.1 上传与设置

用户从今日或知识库选择 PDF。界面显示文件名、页数、大小、支持范围和云端处理说明，然后要求选择学习目标与当前基础。用户确认云端处理后才开始上传。

### 5.2 解析

系统依次展示“读取正文、识别章节、定位知识点、准备目录”四个真实阶段。用户可以离开页面，任务在后台继续。失败后保留文件、解析文本和已完成阶段，不要求重新选择文件。

### 5.3 学习书提案

系统返回推荐书名、一句话概述、3—6 章目录、每章核心知识点、预计阅读时间、原文页码范围和不确定项。用户可以修改书名和章节名、调整顺序、删除章节或合并相邻章节。用户不能把目录扩展到六章以上。

### 5.4 渐进生成

用户确认目录后，系统优先生成第一章，其他章节按顺序后台生成。章节分别具有“等待生成、生成中、可阅读、部分失败、生成失败”状态。一章失败不得阻塞其他章节阅读，重试只作用于失败章节。

### 5.5 阅读与交互

互动学习书提供目录、章节阅读、原文引用跳转、内容块级重新生成、用户笔记、快速验证和章节 Agent 入口。原始 PDF 是事实来源层，不与 AI 生成正文混为同一阅读内容。

### 5.6 章节追问

每个章节均可唤起现有 Agent 抽屉。默认上下文为当前章节、当前内容块及其引用原文；用户可以主动扩大到整本书或添加其他资料。上下文范围必须以可见、可移除的标签呈现。关闭抽屉后再次打开应恢复该学习书中的对话。

### 5.7 验证与后续行动

完成快速验证后，系统记录回答、提示使用、重试、自评、知识点、来源和完成时间，并生成可解释的学习证据。地图显示相关节点的学习状态变化，今日页只突出一个有依据的下一步动作。

## 6. 互动学习书内容模型

### 6.1 层级

```text
InteractiveBook
└── BookChapter
    └── ContentBlock
        ├── Citation
        ├── ConceptReference
        └── UserInteraction
```

### 6.2 MVP 内容块

| 类型 | 职责 | 是否可由 AI 重新生成 |
| --- | --- | --- |
| `explanation` | 核心概念解释 | 是 |
| `example` | 例子或类比 | 是 |
| `formula` | 公式及符号说明 | 是 |
| `citation` | 原文片段、页码和来源跳转 | 只可重新检索，不改原文 |
| `concept` | 知识点、相关概念与候选关系 | 是，用户确认结果除外 |
| `quiz` | 1—2 道快速验证题及反馈 | 是，已提交作答保留 |
| `user_note` | 用户笔记 | 否 |

AI 生成内容和用户内容必须分开存储。重新生成章节或内容块不得覆盖用户笔记、已提交回答、用户确认的目录或用户确认的知识关系。

## 7. Agent 与服务边界

### 7.1 对外形态

用户只看到一个 HarmonyAgent。后端由一个编排器根据产品入口选择固定能力工作流，不向用户暴露多个互相聊天的 Agent。

### 7.2 三项能力工作流

#### 互动学习书生成

读取当前文件、学习目标、当前基础和用户确认目录，写入书、章节、内容块、引用、候选知识点、候选关系和不确定项。该能力不能写入学习状态，也不能声称用户已经学过某个知识点。

#### 深入学习与验证

读取单个知识点、相关章节、原文引用和该知识点的历史学习证据摘要，生成目标、解释、例子、回忆或应用题、反馈和本次学习证据。出题是该工作流的一步，不是无上下文的独立 Agent。

#### 自由问答

读取用户明确选择的当前内容块、当前章节、整本书或主动添加资料，输出回答、实际引用、不确定性和可选的深入学习建议。自由问答只能写入对话记录和用户主动保存的笔记，不能修改学习状态。

### 7.3 确定性服务

- 文件解析与页码定位；
- RAG 检索与引用组装；
- 知识节点、关系、置信度和用户修正存储；
- 学习证据与学习状态规则；
- 今日任务排序；
- 权限、授权、删除和审计元数据。

## 8. 上下文装配

系统不维护一个无限增长的全局提示词，而是按任务装配上下文。

| 任务 | 必需上下文 | 明确排除 |
| --- | --- | --- |
| 目录提案 | PDF 结构化摘要、章节标题、关键片段、学习目标、当前基础、章节上限 | 全部历史对话、其他资料、隐式用户画像 |
| 章节生成 | 已确认目录、当前章目标、相关原文片段、全书简短概述、内容块约束 | 整本 PDF 重复全文、其他章节完整正文 |
| 当前章节追问 | 当前章节内容块、引用原文、最近对话、用户主动添加内容 | 默认搜索全部知识库 |
| 整本书追问 | 目录、章节摘要、检索命中的章节与原文、最近对话 | 全书正文无差别注入 |
| 深入学习 | 当前知识点、相关章节、引用、本次目标、相关证据摘要 | 无关聊天历史、完整用户画像 |

学习习惯与长期记录首版只用于下一步推荐和复习安排，不改变学习书的事实内容。

## 9. 知识地图

MVP 使用“知识空间—主题簇—知识点网络”语义，不采用永久性的严格一级、二级学科树。

- 知识空间是课程、考试、项目或主题范围；
- 互动学习书章节暂时作为主题簇；
- 能够被单独解释、提问和验证的概念成为知识节点；
- 关系类型限定为“前置、包含、相似、对比、应用”；
- 文件和学习书仅作为来源，不作为地图主节点；
- 一个知识点可以关联多个主题簇，但只保存一个节点；
- AI 只生成带引用和置信度的候选关系；
- 用户可以改名、合并、拆分节点以及删除错误关系；
- 节点存在不等于用户已学习，学习状态必须由学习证据推导。

## 10. 信息架构与原型影响

一级入口保持“今日｜学习｜知识库 + Agent”。互动学习书从知识库进入。

| 现有页面或组件 | 设计动作 |
| --- | --- |
| 今日页 | 增加继续解析、继续生成和继续阅读学习书的单一主行动 |
| 知识库 | 增加目录待确认、生成中、部分可读、生成失败、可阅读状态 |
| 文件理解页 | 改为学习书提案与目录确认页 |
| 文档阅读页 | 升级为互动学习书阅读器，原文降为可切换来源层 |
| Agent 抽屉 | 增加当前内容块、当前章节、整本书和主动添加资料的上下文标签 |
| 学习地图 | 章节作为主题簇，节点与关系读取学习书派生数据 |
| 深入学习 | 与章节知识点和测验块建立入口与结果回写 |

现有视觉语言、底部导航、地图手势和 Agent 抽屉形态继续保留。预计可保留约 80% 的视觉与导航结构，页面组件需要约 30%—40% 的调整，数据结构和状态需要约 50%—60% 的重组。该比例为设计估算，不作为代码行数承诺。

## 11. 状态、错误与恢复

核心长任务必须持久化为 `GenerationJob`，记录任务类型、对象 ID、阶段、进度、重试次数、错误类型和最后更新时间。

- PDF 无文本、加密或超限时，上传前或解析早期给出明确原因；
- 目录生成失败时保留解析结果，只重试目录；
- 单章失败时保留其他章节，只重试失败章；
- 内容块与原文不一致时允许查看原文、报告错误、隐藏或单独重新生成；
- Agent 生成中断时保留问题与已生成部分；
- App 重启后恢复上传、生成、阅读、对话和深入学习进度；
- 每条错误信息说明发生了什么、保留了什么以及用户可以做什么。

## 12. 隐私与安全

- 上传前说明 PDF 是否发送到云端、处理目的、保存的派生结果和删除方法；
- 授权记录与文件、学习书、对话和学习证据分开保存；
- API Key 只保存在服务端；
- 普通运行日志不记录完整原文、用户问题和模型回答；
- 审计日志只记录任务 ID、模型、耗时、状态、token 统计和必要错误摘要；
- 用户删除原文件前，系统说明对引用、学习书、地图来源和历史证据的影响；
- 不使用“知识绝不出端”等无法技术保证的绝对表述。

## 13. DeepTutor 源码参考与合规

实现前固定 DeepTutor 上游 commit，并建立 HarmonyAgent 功能到上游文件的映射。重点审阅 Book proposal/spine、page plan、typed block compiler、Page Chat、book references、generation jobs、rebuild、user-note preservation 和 source fingerprints。

可复用的 Apache-2.0 代码必须保留原有版权和归属声明，在修改文件中显著说明改动，并在仓库中保存 Apache-2.0 许可证和第三方归属文档。DeepTutor 名称与 Logo 不作为 HarmonyAgent 品牌使用。第三方字体、图标、模型、数据和素材按各自许可证单独核查。

DeepTutor 的 Next.js 页面不直接嵌入鸿蒙端。交互机制和数据结构可以参考或依法复用，界面组件按 ArkUI 原生触控、安全区、系统返回和多设备语义重新实现。

## 14. MVP 验收标准

使用一份约 20 页的文本型 PDF，在目标移动设备或对应高保真原型中完整验证：

1. 成功提取正文、结构和页码；
2. 生成 3—6 章目录；
3. 用户修改目录后能够保存并影响后续生成；
4. 确认后第一章优先生成；
5. 每章包含解释、引用和快速验证题；
6. 引用能够跳回正确原文位置；
7. 当前章节追问不错误携带其他资料；
8. Agent 回答展示实际使用的引用；
9. 完成验证后生成可解释的学习证据；
10. 地图显示章节主题簇、知识点和候选关系；
11. 今日页出现一个有依据的下一步；
12. 单章失败可以独立重试；
13. App 重启后能够恢复生成和阅读进度；
14. 用户笔记、已提交回答和已确认关系不会被重新生成覆盖。

## 15. 后续阶段

第一轮闭环稳定后，后续阶段按价值和风险依次考虑：多文件合书、Markdown 与 Office 文档、OCR、更多内容块、来源漂移检测、长期学习者模型、端侧模型、系统分享、小艺、通知、平板和手表协同。后续能力不得反向破坏本规格确立的可追溯、可修正和写入权限边界。
