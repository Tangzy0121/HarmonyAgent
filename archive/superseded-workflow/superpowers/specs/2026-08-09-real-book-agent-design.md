# 互动学习书真实问答 Agent 设计

## 1. 目标

把当前互动学习书中的固定演示回答替换为可实际使用的 DeepSeek 流式问答。用户从某一章或某一内容块发起追问时，Agent 必须知道当前阅读位置，只能基于前端明确发送的学习书内容与原文片段回答，并把使用过的依据呈现为可核对的引用卡片。

本阶段不读取真实 PDF、不建立向量库、不实现长期记忆，也不让自由问答写入学习掌握度。真实 PDF 检索和持久化属于后续阶段。

## 2. DeepTutor 源码参考与取舍

参考基线为 HKUDS/DeepTutor `v1.5.10`，commit `8865da7c6d51d579db66ad123fcf3f16a2eed0a4`。

采用以下边界：

- `deeptutor/book/context.py`：上下文构建保持纯函数；先规范化引用，再按书、页、块序列化；隐藏块不进入上下文；每块、每页、总上下文都有字符预算；缺失对象产生非致命 warning。
- `web/app/(workspace)/book/components/BookChatPanel.tsx`：书页问答自动携带当前页引用；对话按页面/会话隔离；流式消息有 busy、done、error 状态；切换页面时清理旧连接和临时状态。
- `deeptutor/agents/chat/agent_loop.py`：一次用户提问是一轮有明确终止条件的流式 turn；内容、错误、来源和完成信号分开传递；上游失败不能伪装成正常回答。
- `deeptutor/services/session/source_inventory.py`：来源记录独立于回答正文，后续可以从内联上下文无缝替换成 RAG 检索来源。

不采用 DeepTutor 的完整工具循环、知识库、多 Agent、附件系统和三层记忆。HarmonyAgent 第一阶段只有一个受约束的学习书问答能力，避免把通用 Agent 平台提前搬入 MVP。

不复制 DeepTutor 的代码、品牌、文案或视觉资产，只参考模块职责与数据流。

## 3. 方案选择

采用专用接口 `POST /api/agent/book-chat`，不让浏览器直接调用通用 `/api/chat/completions`。

专用接口的优点是：服务端可以统一校验请求、裁剪上下文、生成系统提示词、固定模型参数和隐藏 API Key；前端只负责表达用户当前位置与渲染事件。后续接入真实 PDF RAG 时，接口契约可以保持不变，只替换服务端的上下文来源。

## 4. 模块边界

### 4.1 前端上下文构建器

新增纯函数模块，将 `LearningBook` 和当前选择转换为 `BookAgentContext`。它不调用网络，也不读取全局状态。

输入包括：

- `book`：当前互动学习书；
- `activeChapterId`：当前章节；
- `scope`：`chapter` 或 `book`；
- `focusBlockId`：可选，表示用户从哪一段进入追问。

输出包括：

- 书名、学习目标与范围标签；
- 有序章节摘要；
- 有序内容块文本；
- 编号来源 `S1...Sn`，每条保留文件名、页码、摘录和来源内容块；
- 非致命 warnings，例如章节不存在、块尚未生成或内容被截断。

预算固定为：单块最多 2,000 字符、单章最多 8,000 字符、整次请求最多 24,000 字符、最近对话最多 6 条。优先保留聚焦块，再保留其来源，最后按阅读顺序补充其余块。用户笔记可以作为“用户提供的补充信息”进入上下文，但不得伪装成原文来源；隐藏、pending、generating 和 error 块不发送给模型。

### 4.2 服务端学习书 Agent

服务端新增独立路由和纯提示词构建器。请求体只接受白名单字段，限制问题、历史记录、块和来源数量；无效请求返回 400，未配置 Key 返回 503，上游鉴权失败返回 502，客户端取消时停止继续转发。

系统提示词要求模型：

- 使用简体中文、解释清楚但不过度扩写；
- 只根据提供的学习书上下文回答；
- 事实依据使用 `[S1]` 格式；
- 无依据时明确说“当前学习书内容中没有足够依据”；
- 区分原文来源和用户笔记；
- 不伪造页码、来源或学习掌握状态；
- 不执行工具调用，也不修改任何学习数据。

模型由服务端环境变量决定，当前为 `deepseek-v4-flash`。前端不能覆盖 base URL、API Key 或模型名称。

### 4.3 流式协议

接口返回 `text/event-stream`，每条事件使用 JSON 数据：

- `start`：请求已接受，返回 turn id；
- `delta`：一个回答文本增量；
- `sources`：本轮可用的编号来源清单；
- `done`：回答结束，包含 usage（若上游提供）；
- `error`：可安全展示的错误码和中文提示。

服务端把 DeepSeek 的 OpenAI-compatible SSE 转换成上述内部事件，禁止把供应商原始错误体、请求头或 Key 传给浏览器。若模型引用不存在的编号，前端只渲染实际存在的来源卡，不制造缺失来源。

### 4.4 Agent 抽屉

现有 `AgentDrawer` 保留 75% 高度、全屏切换、历史入口和上下文移除交互，但消息状态从内部 mock 数据移到 App 管理的按上下文会话状态。

状态机为：`idle → streaming → complete | error | cancelled`。用户可以停止生成、在失败后重试、继续追问；流式过程中禁止重复提交。切换章节后创建/恢复该章节的独立会话，不把上一章对话混入新上下文。整本书范围与章节范围也使用不同会话键。

从某一内容块点击“深入学习这一段/向 Agent 提问”时，抽屉显示聚焦块标签；首次请求优先发送该块。移除上下文后允许普通对话，但本阶段仍经过同一服务端接口，并明确显示“未附加学习书依据”。

回答正文支持普通文本和引用标记；已引用的 `S` 编号在回答下方渲染为来源卡片，显示文件名、页码和短摘录。点击卡片在当前原型中滚动或切换到对应章节/内容块，不假装打开尚不存在的 PDF 预览。

## 5. 数据流

1. 用户打开学习书并选择章节或聚焦内容块。
2. `buildBookAgentContext` 根据范围和预算生成上下文与来源清单。
3. 前端将问题、最近 6 条消息和结构化上下文提交给 `/api/agent/book-chat`。
4. 服务端校验并构建 DeepSeek 消息，调用 `deepseek-v4-flash` 流式接口。
5. 服务端转译为内部 SSE；前端增量更新当前 Agent 消息。
6. `sources` 事件形成引用卡片；`done` 固化本轮消息；`error` 保留用户问题并提供重试。
7. 本轮问答只更新会话 UI，不写 `LearningEvidence`、知识地图或今日任务。

## 6. 错误与隐私

- API Key 只存在于被 Git 忽略的 `server/.env`；日志不得输出 Authorization、请求正文或完整上下文。
- 客户端只发送当前选择需要的内容，不发送整本未选资料。
- 问题为空、上下文超限、历史角色非法、来源编号重复时在服务端拒绝或规范化。
- 网络断开、429、上游 5xx 和格式异常使用稳定内部错误码；UI 保留问题并允许重试。
- 用户主动停止使用 `AbortController`；被取消的回答标记为“已停止”，不当作完整答案。
- 服务端设置请求超时和最大响应体预算，防止流长期悬挂。

## 7. 测试与验收

### 自动化测试

- 上下文构建：章节/整书范围、聚焦块优先、字符预算、隐藏/未生成块过滤、用户笔记非来源、warnings。
- 服务端提示词：引用规则、无依据规则、字段裁剪、密钥不进入响应。
- SSE 转译：分片 JSON、跨 chunk 边界、`[DONE]`、上游错误、客户端取消。
- 前端会话：真实问题进入请求、delta 累积、停止、重试、章节切换隔离、自由问答不写学习证据。

### 真实验收路径

在 390 × 844px 视口完成：进入第一章 → 聚焦一个内容块 → 打开 Agent → 提问“为什么有标签才算监督学习？” → 看到流式回答和第 4–6 页引用 → 继续追问 → 停止一次生成 → 重试成功 → 切换第二章确认对话不串章 → 回到第一章恢复本地会话。控制台无错误，页面无横向溢出。

## 8. 明确不做

- 不上传或解析真实 PDF；
- 不做 embedding、向量检索或 GraphRAG；
- 不持久化跨刷新会话；
- 不开放模型选择和任意系统提示词；
- 不增加通用工具调用、Web 搜索或子 Agent；
- 不把自由问答结果计入掌握度；
- 不迁移 ArkUI/ArkTS 页面。

这些能力分别在后续“真实文档生成”“学习状态持久化”和“鸿蒙原生迁移”阶段设计。
